# 软件设计师（中级）考点精讲（数据库）

## 5.1 数据库系统概述：三级模式与两级映像

数据库管理系统（DBMS）是管理数据库的软件，数据库系统由数据库、DBMS、应用系统、数据库管理员和用户构成。数据库系统采用三级模式两级映像体系结构：外模式（用户模式、子模式）是用户看到的局部数据视图，对应视图；概念模式（模式、逻辑模式）是全体数据的全局逻辑结构，对应基本表；内模式（存储模式）是数据的物理存储结构，对应存储文件。外模式与概念模式之间的映像保证逻辑数据独立性，概念模式与内模式之间的映像保证物理数据独立性。逻辑数据独立性是指概念模式改变时，只需修改外模式与概念模式的映像而不用修改应用程序；物理数据独立性是指内模式改变时，只需修改概念模式与内模式的映像而概念模式不变。数据库的数据具有数据共享性高、冗余度低、数据独立性高和统一管理与控制的特点。数据库管理员（DBA）负责数据库的设计、运行维护、备份恢复和安全控制。

## 5.2 E-R 模型与转换为关系模式

E-R 模型（实体联系模型）用实体、属性和联系描述现实世界。实体是客观存在可区分的事物，属性是实体的特性，联系是实体之间的关系。联系有一对一（1:1）、一对多（1:n）和多对多（m:n）三种类型。E-R 图中，实体用矩形表示，属性用椭圆表示，联系用菱形表示，并用无向边连接。E-R 图转换为关系模式的规则：每个实体转换为一个关系模式，实体的属性就是关系的属性，实体的码就是关系的码；1:1 联系可以与任意一端的实体合并，或单独转换为一个关系模式；1:n 联系可以与 n 端的实体合并，把 1 端实体的码加入 n 端关系作为外码；m:n 联系必须单独转换为一个关系模式，其属性由两端实体的码和联系自身的属性组成，关系的码是两端实体码的组合。多值属性要单独建立关系。

## 5.3 关系模型：键与完整性约束

关系模型用二维表表示实体及实体之间的联系，一个关系对应一张二维表，表中的一行称为元组，一列称为属性，属性的取值范围称为域。关系中的元组不能重复，元组的顺序和属性的顺序都无关紧要，每个属性值必须是不可再分的原子值。候选码是能唯一标识元组且不含多余属性的最小属性组，一个关系可以有多个候选码，从中选定一个作为主码。包含在任一候选码中的属性称为主属性，不包含在任何候选码中的属性称为非主属性。外码是本关系的某个属性组，它是另一个关系的主码，用于表示两个关系之间的联系。关系的完整性约束包括实体完整性、参照完整性和用户定义完整性：实体完整性要求主码不能取空值；参照完整性要求外码的取值要么为空，要么等于被参照关系中某个元组的主码值；用户定义完整性是针对具体应用的语义约束。

## 5.4 关系代数

关系代数的基本运算有并、差、笛卡尔积、选择和投影，其他运算如交、连接、除可由基本运算导出。并、交、差运算要求两个关系具有相同的属性个数且对应属性的域相同。选择运算从关系中选出满足条件的元组，是对行的操作；投影运算从关系中选出若干属性列并去掉重复元组，是对列的操作。笛卡尔积的结果元组数是两个关系元组数之积，属性数是两个关系属性数之和。连接运算是从笛卡尔积中选取满足连接条件的元组，自然连接要求两个关系有公共属性，按公共属性值相等连接，并在结果中去掉重复的公共属性列。等值连接是连接条件为相等比较的连接，自然连接是特殊的等值连接。除运算常用来回答含有“全部”的查询。例如关系 R 有 3 个元组 2 个属性，关系 S 有 4 个元组 3 个属性，则 R×S 有 12 个元组和 5 个属性。

## 5.5 SQL 的数据定义与数据操纵

SQL 分为数据定义语言（DDL）、数据操纵语言（DML）、数据控制语言（DCL）和事务控制语言。DDL 包括 CREATE、ALTER 和 DROP，用于创建、修改和删除表、视图、索引；DML 包括 SELECT、INSERT、UPDATE 和 DELETE；DCL 包括 GRANT 和 REVOKE。创建表时可以定义约束：PRIMARY KEY 主键约束保证唯一且非空，FOREIGN KEY 外键约束维护参照完整性，UNIQUE 约束保证取值唯一但允许空值，NOT NULL 约束禁止空值，CHECK 约束限制取值范围，DEFAULT 指定默认值。INSERT 语句向表中插入元组；UPDATE 语句配合 SET 和 WHERE 修改满足条件的元组；DELETE 语句配合 WHERE 删除满足条件的元组，省略 WHERE 则删除全部元组但保留表结构。DROP TABLE 会删除表的结构和数据，ALTER TABLE 可以增加、修改或删除列。

## 5.6 SQL 查询：分组、连接、子查询与视图

SELECT 语句的基本形式是 SELECT 列表 FROM 表 WHERE 条件 GROUP BY 分组列 HAVING 分组条件 ORDER BY 排序列。WHERE 子句在分组之前过滤行，HAVING 子句在分组之后过滤分组，HAVING 中可以使用聚合函数而 WHERE 中不能。聚合函数有 COUNT、SUM、AVG、MAX 和 MIN，COUNT(*) 统计行数，COUNT(列) 不统计该列为 NULL 的行，聚合函数通常忽略 NULL 值。DISTINCT 用于去掉重复行。ORDER BY 默认升序，降序用 DESC。模糊查询用 LIKE，百分号匹配任意长度的字符，下划线匹配单个字符。判断空值要用 IS NULL 或 IS NOT NULL，不能用等号。IN 表示属于某个集合，BETWEEN 表示在闭区间内。连接查询有内连接、左外连接、右外连接和全外连接，左外连接保留左表的全部行，右表无匹配时补 NULL。子查询嵌套在另一个查询中，EXISTS 判断子查询结果是否非空。视图是由查询定义的虚表，不存储数据，用 CREATE VIEW 创建。授权使用 GRANT 权限 ON 对象 TO 用户，收回权限使用 REVOKE。

## 5.7 函数依赖、Armstrong 公理与候选码

函数依赖 X → Y 表示属性集 X 的值决定属性集 Y 的值：若两个元组在 X 上取值相等则在 Y 上取值也必相等。若 Y 是 X 的子集，则 X → Y 是平凡函数依赖。若 X → Y，且对 X 的任何真子集 X'，都有 X' 不能决定 Y，则 Y 完全函数依赖于 X，否则称为部分函数依赖。若 X → Y、Y → Z 且 Y 不能决定 X，则 Z 传递函数依赖于 X。Armstrong 公理包括自反律（若 Y 是 X 的子集则 X → Y）、增广律（若 X → Y 则 XZ → YZ）和传递律（若 X → Y 且 Y → Z 则 X → Z）。由此还可导出合并律（X → Y 且 X → Z 则 X → YZ）、分解律（X → YZ 则 X → Y 且 X → Z）和伪传递律。属性集 X 的闭包 X+ 是由 X 通过函数依赖集 F 能推出的所有属性的集合。求候选码的方法：在函数依赖集中从不出现在任何依赖右部的属性必须属于候选码；如果这些属性的闭包包含了全部属性，它们就是候选码。例如关系 R(A, B, C, D)，F = {A → B, B → C}，D 和 A 从不出现在右部，AD 的闭包是 ABCD，所以 AD 是候选码。

## 5.8 范式与模式分解

在第一范式（1NF）基础上，消除非主属性对候选码的部分函数依赖得到 2NF；在 2NF 基础上消除非主属性对候选码的传递函数依赖得到 3NF；在 3NF 基础上，要求每个决定因素都包含候选码则得到 BCNF。如果候选码只由单个属性组成，则关系一定不存在部分函数依赖，所以属于 2NF；如果关系中所有属性都是主属性，则一定属于 3NF。范式的级别关系是 1NF 包含 2NF，2NF 包含 3NF，3NF 包含 BCNF。模式分解要保持无损连接性和函数依赖。无损连接是指分解后的关系通过自然连接能恢复原关系，不丢失信息，也不产生多余元组；保持函数依赖是指分解后的关系保持原有的函数依赖集。分解成 3NF 既能保持函数依赖又具有无损连接性，分解成 BCNF 可以保证无损连接但不一定保持函数依赖。对于二分解，若 R1 与 R2 的公共属性能决定 R1 或 R2 的全部属性，则分解是无损连接的。

## 5.9 事务与并发控制

并发操作可能引起丢失修改、不可重复读、读脏数据和幻读等数据不一致问题。丢失修改是两个事务读入同一数据并修改，后提交的覆盖了先提交的结果；不可重复读是同一事务两次读同一数据得到不同结果，因为中间被其他事务修改或删除；读脏数据是读取了其他事务未提交的修改，而该事务随后回滚；幻读是同一事务两次按条件查询得到的记录数不同，因为其他事务插入了新记录。封锁是解决并发问题的主要手段：排他锁只允许持锁事务读写，其他事务不能加任何锁；共享锁允许多个事务同时读，但不能写。三级封锁协议：一级协议要求修改前加排他锁直到事务结束，防止丢失修改；二级协议在一级基础上读前加共享锁读完即释放，防止读脏数据；三级协议要求读前加共享锁直到事务结束，防止不可重复读。两段锁协议要求事务分为加锁阶段和解锁阶段，加锁阶段只加锁不解锁，解锁阶段只解锁不加锁，遵守两段锁协议可以保证并发调度的可串行化，但不能避免死锁。SQL 标准的四种隔离级别由低到高为读未提交、读已提交、可重复读和串行化，隔离级别越高并发度越低。

## 5.10 数据库恢复与备份

数据库故障分为事务故障、系统故障和介质故障。事务故障是事务内部的错误导致事务无法正常完成，恢复方法是撤销该事务已做的修改；系统故障如掉电、系统崩溃，内存中的数据丢失，恢复时需要重做已提交事务、撤销未提交事务；介质故障是磁盘损坏，需要用备份和日志文件恢复。日志文件记录事务对数据库的更新操作，写日志文件必须遵守先写日志后写数据库的原则。检查点技术在日志中设置检查点，恢复时只需处理检查点之后的事务，缩短恢复时间。数据库备份分为完全备份、增量备份和差异备份：完全备份备份全部数据，增量备份只备份上次备份以来变化的数据，差异备份备份上次完全备份以来变化的数据。恢复时增量备份需要依次恢复所有增量备份，差异备份只需要恢复最近一次差异备份。

## 5.11 索引、视图、触发器与存储过程

索引是对表中一列或多列的值进行排序的数据结构，可以加快查询速度，但会降低插入、删除和更新的速度并占用存储空间。常见索引有 B+ 树索引、哈希索引和位图索引，B+ 树索引适合范围查询，哈希索引只适合等值查询。聚集索引决定数据行的物理存储顺序，一个表只能有一个聚集索引，非聚集索引可以有多个。视图是由查询定义的虚表，可以简化查询、提供数据安全性和逻辑独立性，对视图的更新受限，包含聚合函数或分组的视图通常不能更新。触发器是在对表进行插入、删除或更新操作时自动执行的程序，常用于实现复杂的完整性约束和审计。存储过程是预先编译并存储在数据库服务器中的一组 SQL 语句，可以接收参数，减少网络传输并提高执行效率。游标用于逐行处理查询结果集。

## 5.12 分布式数据库、数据仓库与 NoSQL

分布式数据库的数据物理上分散在不同节点、逻辑上是一个整体，具有分布透明性，包括分片透明、位置透明和复制透明。数据仓库是面向主题的、集成的、相对稳定的、反映历史变化的数据集合，用于支持管理决策。数据仓库主要用于联机分析处理，而传统数据库用于联机事务处理。数据挖掘是从大量数据中发现隐含规律的过程，常见任务有分类、聚类、关联规则和预测，经典的关联规则例子是购物篮分析。NoSQL 数据库放宽了关系型数据库的一致性要求以获得更好的扩展性，类型包括键值存储、文档数据库、列族数据库和图数据库。CAP 理论指出分布式系统不可能同时满足一致性、可用性和分区容错性，最多只能同时满足其中两项。
