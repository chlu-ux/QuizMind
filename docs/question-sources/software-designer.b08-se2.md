# 软件设计师（中级）考点精讲（软件工程（下）：测试、维护与项目管理）

## 8.8 软件测试基础：原则、阶段与测试策略

软件测试的目的是发现软件中的错误，而不是证明软件没有错误；成功的测试是发现了至今尚未发现的错误的测试。测试的原则包括：尽早和不断地测试、避免由程序开发者本人测试自己的程序、穷举测试不可能、发现错误有群集现象，即大部分错误集中在少数模块。测试分为静态测试和动态测试：静态测试不运行程序，如代码审查、走查和静态分析；动态测试需要运行程序。单元测试针对最小的模块，常用驱动模块和桩模块：驱动模块模拟被测模块的上级模块调用它，桩模块模拟被测模块调用的下级模块。集成测试有非渐增式和渐增式两类，渐增式包括自顶向下、自底向上和三明治；自顶向下需要桩模块，自底向上需要驱动模块。确认测试有 α 测试和 β 测试：α 测试在开发者现场由用户进行，β 测试在用户现场由用户进行，开发者不在场。调试的目的是定位并改正错误，测试的目的是发现错误。

## 8.9 白盒测试：逻辑覆盖与环路复杂度

白盒测试根据程序内部的逻辑结构设计测试用例，也叫结构测试。逻辑覆盖标准按强度由弱到强依次为：语句覆盖，即每条语句至少执行一次；判定覆盖，即每个判定的真假分支至少各执行一次；条件覆盖，即每个判定中每个条件的真假取值至少各出现一次；判定条件覆盖；条件组合覆盖，即每个判定中条件的各种组合都至少出现一次；路径覆盖，即程序中所有可能的执行路径至少执行一次。语句覆盖最弱，路径覆盖最强，但路径覆盖在有循环时路径数可能无限。判定覆盖也称分支覆盖，能够保证语句覆盖，但不一定能保证条件覆盖。环路复杂度 V(G) 等于控制流图中的边数减结点数加 2，也等于判定结点数加 1，它给出了基本路径测试所需独立路径数的上界。基本路径测试根据环路复杂度导出独立路径集并设计测试用例。

## 8.10 黑盒测试：等价类、边界值与测试类型

黑盒测试根据软件的功能说明设计测试用例，不考虑程序内部结构，也叫功能测试。常用方法有等价类划分、边界值分析、因果图、决策表和错误推测法。等价类划分把输入域分成若干等价类，从每个等价类中选一个代表值测试，分为有效等价类和无效等价类；设计测试用例时，每个有效等价类应尽量多地被一个用例覆盖，每个无效等价类必须单独用一个用例覆盖。边界值分析选取输入输出的边界值及其附近的值作为测试数据，因为大量错误发生在边界上，如输入范围为 1 到 100，应取 0、1、2、99、100、101 等值。因果图方法分析输入条件与输出结果之间的因果关系，适合输入条件组合较多的场合。错误推测法凭经验和直觉推测可能出现的错误来设计用例。性能测试检验系统在不同负载下的响应时间和吞吐量，压力测试检验系统在超出正常负载下的表现，兼容性测试检查软件在不同环境下的运行情况，回归测试确认修改后没有引入新错误。

## 8.11 软件维护与软件质量

软件维护分为四类：改正性维护修正运行中发现的错误；适应性维护使软件适应环境变化，如操作系统升级；完善性维护增加新功能或改进性能，占维护工作量的比例最大；预防性维护为将来的维护做准备，提高可维护性和可靠性。可维护性的决定因素有可理解性、可测试性、可修改性、可靠性、可移植性、可使用性和效率。软件质量模型 ISO/IEC 25010 包含功能适合性、性能效率、兼容性、易用性、可靠性、信息安全性、维护性和可移植性八个质量特性。McCall 质量模型从产品运行、产品修改和产品转移三个方面描述质量因素。软件可靠性是在规定条件和规定时间内无故障完成规定功能的能力。软件质量保证的主要活动有评审、测试、标准与度量。技术评审、走查和审查是常用的静态质量保证手段。

## 8.12 项目管理：WBS、甘特图、PERT 与关键路径

项目管理的主要内容包括范围、进度、成本、质量、人力资源、沟通、风险、采购和干系人管理。工作分解结构把项目分解为可管理的工作包，是进度和成本管理的基础。甘特图用横条表示任务的起止时间，直观显示进度和并行关系，但不能清晰表示任务之间的依赖关系。PERT 图用结点和箭线表示任务及依赖关系，可以计算关键路径。关键路径是项目中最长的路径，决定项目的最短工期，关键路径上的任务总时差为 0。最早开始时间等于所有紧前任务最早完成时间的最大值，最早完成时间等于最早开始时间加持续时间，最晚开始时间等于最晚完成时间减持续时间，总时差等于最晚开始时间减最早开始时间。自由时差是在不影响紧后任务最早开始的前提下本任务可以延迟的时间。三点估算法的期望工期等于乐观时间加四倍最可能时间再加悲观时间之和除以 6，标准差等于悲观时间减乐观时间之差除以 6。

## 8.13 软件成本估算与度量

软件成本估算方法有类比法、专家判断法、自顶向下和自底向上估算、参数模型。COCOMO 是常用的参数模型，基本 COCOMO 把项目分为组织型、半独立型和嵌入型三类，估算工作量时以千行代码数 KLOC 为主要输入。功能点方法根据系统的外部输入、外部输出、外部查询、内部逻辑文件和外部接口文件五类功能的数量和复杂度计算未调整功能点，再乘以技术复杂度调整因子得到功能点数，它与实现语言无关，适合在项目早期估算规模。代码行方法简单直观，但与实现语言有关。软件度量包括规模度量、复杂度度量、质量度量和进度度量。Brooks 定律指出，向进度落后的项目中增加人员只会使进度更加落后。

## 8.14 风险管理与配置管理

风险管理的过程包括风险识别、风险分析与评估、风险应对计划和风险监控。风险的两个基本属性是不确定性和损失。风险值等于风险发生的概率乘以风险造成的损失。常见的风险应对策略有规避、转移、减轻和接受。配置管理对软件开发过程中的各种产物进行标识、控制和版本管理，主要活动有配置标识、版本控制、变更控制、配置状态报告和配置审计。配置项包括需求规格说明书、设计文档、源代码、测试用例和用户手册等。基线是经过正式评审并批准的配置项集合，作为后续开发的基础，基线之后的修改必须通过正式的变更控制流程。配置管理中，开发库保存正在开发的配置项，受控库保存已评审通过的基线配置项，产品库保存已发布的产品。变更控制的一般流程是提出变更申请、评估影响、变更控制委员会审批、实施变更和验证发布。

## 8.15 能力成熟度、软件复用、再工程与 CASE

能力成熟度模型集成（CMMI）把过程改进分为五个成熟度等级：初始级、已管理级、已定义级、定量管理级和优化级。初始级的过程无序、不可预测；已管理级有项目级的基本管理；已定义级有组织级的标准过程；定量管理级用数据量化管理过程；优化级持续改进。ISO 9000 是质量管理体系标准，强调过程控制和持续改进。软件复用是利用已有的软件成果构造新软件，可以提高生产率和质量、降低成本，复用的对象包括代码、设计、需求、测试用例和文档，软件构件和框架是重要的复用形式。软件再工程包括逆向工程、重构和正向工程：逆向工程从已有系统的代码中恢复设计和需求；重构在不改变外部行为的前提下改善代码内部结构。CASE 工具是支持软件开发活动的工具，上游 CASE 支持需求分析和设计，下游 CASE 支持编码和测试，集成 CASE 覆盖整个生命周期。

## 8.16 形式化方法、净室工程与软件文档

形式化方法用严格的数学语言描述软件的需求和设计，可以通过推理证明程序的正确性，常见的形式化规格说明语言有 Z 语言和 VDM。形式化方法适用于安全关键系统，缺点是学习和使用成本高。净室软件工程强调在开发阶段通过严格的数学验证和统计测试来避免缺陷，而不是依赖调试，增量开发和统计质量控制是它的特点。软件文档分为开发文档、管理文档和用户文档：开发文档包括可行性研究报告、需求规格说明书、设计说明书和测试计划等，管理文档包括项目计划和进度报告，用户文档包括用户手册和操作手册。文档应该完整、准确、一致并与软件版本保持同步。
