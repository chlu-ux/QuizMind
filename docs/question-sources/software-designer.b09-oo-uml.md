# 软件设计师（中级）考点精讲（面向对象与 UML）

## 9.1 面向对象基本概念

面向对象方法把现实世界的事物抽象为对象，对象是属性和方法的封装体，具有标识、状态和行为。类是具有相同属性和方法的对象的抽象，对象是类的实例。封装隐藏对象的内部状态，只通过公开的接口访问；继承使子类获得父类的属性和方法，并可扩展或重写，Java 只支持单继承，C++ 支持多继承；多态是同一消息被不同对象接收时产生不同的行为，分为编译时多态和运行时多态，运行时多态通过重写和动态绑定实现。抽象类不能被实例化，可以包含抽象方法，由子类实现；接口只定义行为规范，一个类可以实现多个接口。消息是对象之间通信的方式，一个对象通过向另一个对象发送消息来请求服务。构造函数用于创建对象时初始化对象状态，析构函数在对象销毁时执行清理工作。

## 9.2 重载与重写，静态绑定与动态绑定

重载是在同一个类中定义多个同名但参数列表不同的方法，与返回值类型无关，在编译时根据参数确定调用哪个方法，属于静态绑定。重写是子类重新定义父类中已有的方法，方法名、参数列表相同，运行时根据对象的实际类型决定调用哪个方法，属于动态绑定，是实现运行时多态的基础。静态绑定在编译时确定调用的方法，速度快；动态绑定在运行时确定，更灵活。重写时子类方法的访问权限不能比父类更严格。私有方法、静态方法和构造方法不能被重写。向上转型是把子类对象赋给父类引用，是安全的；向下转型需要强制类型转换，可能失败。

## 9.3 面向对象分析与设计过程及设计原则

面向对象分析识别问题域中的对象、类及其关系，建立分析模型；面向对象设计在分析模型基础上细化类的设计并考虑实现环境；面向对象编程用程序语言实现设计。面向对象设计原则：单一职责原则要求一个类只负责一项职责；开闭原则要求软件实体对扩展开放、对修改关闭；里氏替换原则要求子类对象能够替换父类对象而不影响程序的正确性；依赖倒置原则要求高层模块不应依赖低层模块，二者都应依赖抽象，面向接口编程；接口隔离原则要求使用多个专门的接口比使用单一的总接口好；迪米特法则又称最少知识原则，一个对象应尽可能少地了解其他对象，只与直接的朋友通信；合成复用原则要求优先使用组合或聚合而不是继承来复用代码。开闭原则是面向对象设计的总原则，其他原则是实现开闭原则的手段。

## 9.4 UML 概述：事物、关系、图与视图

UML 是一种可视化的建模语言，由事物、关系和图三部分组成。UML 中的事物分为结构事物、行为事物、分组事物和注释事物，结构事物包括类、接口、用例、构件和节点，行为事物包括交互和状态机，分组事物主要是包。UML 的关系有依赖、关联、泛化和实现四种。UML 2.x 共有 14 种图，分为结构图和行为图两大类：结构图包括类图、对象图、构件图、组合结构图、包图、部署图和轮廓图；行为图包括用例图、活动图、状态机图和交互图，交互图又包括顺序图、通信图、交互概览图和时序图。UML 的 4+1 视图包括逻辑视图、进程视图、实现视图、部署视图和用例视图，其中用例视图是核心，驱动其他四个视图。

## 9.5 用例图：参与者与用例间关系

用例图描述系统的功能需求，由参与者、用例和系统边界以及它们之间的关系组成。参与者是与系统交互的外部实体，可以是人、外部系统或设备，用小人图形表示；用例是系统提供的一个完整的功能单元，用椭圆表示；系统边界用矩形框表示。用例之间的关系有包含、扩展和泛化。包含关系表示一个用例的行为包含另一个用例的行为，被包含的用例是必须执行的，箭头由基用例指向被包含用例；扩展关系表示在特定条件下基用例的行为可以被扩展用例增强，扩展用例是可选的，箭头由扩展用例指向基用例。参与者与用例之间是关联关系，参与者之间、用例之间可以有泛化关系。

## 9.6 类图：类间关系与多重度

类图描述类、接口以及它们之间的静态关系。类用矩形分三层表示：类名、属性、方法。可见性符号：加号表示公有，减号表示私有，井号表示受保护，波浪号表示包内可见。类之间的关系有：依赖用虚线箭头表示，一个类使用另一个类，如方法的参数；关联用实线表示，一个类持有另一个类的引用；聚合用空心菱形表示整体与部分的关系，部分可以脱离整体独立存在；组合用实心菱形表示整体与部分的关系，部分不能脱离整体，整体消亡部分随之消亡；泛化用空心三角箭头实线表示继承，子类指向父类；实现用空心三角箭头虚线表示，类实现接口。关联的多重度表示参与关联的对象个数，如 1 表示恰好一个，0..1 表示零个或一个，0..* 表示零个或多个，1..* 表示一个或多个。从弱到强的关系强度大致是：依赖、关联、聚合、组合、泛化。抽象类的名称用斜体表示。

## 9.7 动态模型：顺序图、通信图、状态图与活动图

顺序图强调对象之间消息传递的时间顺序，对象在顶部横向排列，每个对象有一条垂直的生命线，消息用水平箭头表示，同步消息用实心箭头，返回消息用虚线箭头，激活条表示对象正在执行操作。通信图强调对象之间的结构关系和消息传递，消息用带序号的箭头表示，与顺序图语义等价，可以相互转换。状态图描述一个对象在生命周期内的状态以及在事件触发下的状态转换，包含初始状态、终止状态、状态、转换、事件和动作，其中初始状态用实心圆表示，适合描述单个对象的行为。活动图描述业务流程或操作的控制流，包含初始节点、活动、判定、分叉与汇合、泳道和终止节点，适合描述并行流程，泳道用来区分不同的负责者。

## 9.8 实现模型：构件图、部署图、包图与 UML 扩展机制

构件图描述系统的物理构件及构件之间的依赖关系，用于表示软件的物理组织结构。部署图描述系统运行时的硬件节点、节点之间的连接以及构件在节点上的分布，用于表示系统的物理部署。包图用来把模型元素组织成包，描述包之间的依赖关系，用于管理复杂模型。对象图是类图在某个时刻的实例快照，表示对象及对象之间的链接。UML 的扩展机制包括构造型、标记值和约束，可以在不改变 UML 元模型的情况下扩展 UML 的表达能力，其中构造型用双尖括号括起来的名称表示。

## 9.9 设计模式概述：分类与基本概念

设计模式是对软件设计中反复出现的问题的经典解决方案。《设计模式》一书总结了 23 种设计模式，按目的分为创建型、结构型和行为型三类。创建型模式关注对象的创建，共 5 种：单例、工厂方法、抽象工厂、建造者和原型。结构型模式关注类和对象的组合，共 7 种：适配器、桥接、组合、装饰器、外观、享元和代理。行为型模式关注对象之间的职责分配与通信，共 11 种：责任链、命令、解释器、迭代器、中介者、备忘录、观察者、状态、策略、模板方法和访问者。按范围又分为类模式和对象模式：类模式处理类与子类的关系，通过继承建立，在编译时确定；对象模式处理对象间的关系，通过组合建立，运行时可以变化，大多数模式是对象模式。设计模式的四个基本要素是模式名称、问题、解决方案和效果。
