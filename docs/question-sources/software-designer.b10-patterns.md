# 软件设计师（中级）考点精讲（设计模式）

## 9.10 创建型模式（一）：单例、工厂方法与抽象工厂

单例模式保证一个类只有一个实例，并提供全局访问点；实现要点是私有构造函数、静态私有实例和公有静态获取方法，常见的实现有饿汉式和懒汉式，饿汉式在类加载时创建实例，懒汉式在第一次使用时创建实例，多线程下需要同步，单例适用于配置管理器、线程池和日志对象等。工厂方法模式定义创建对象的接口，让子类决定实例化哪个类，使类的实例化延迟到子类，包含抽象产品、具体产品、抽象工厂和具体工厂四个角色，每增加一个产品只需增加一个具体产品和对应的具体工厂，符合开闭原则。抽象工厂模式提供一个创建一系列相关或相互依赖对象的接口，而无需指定它们的具体类，适用于产品族的创建，如不同操作系统风格的界面组件；增加新的产品族容易，但增加新的产品等级结构困难。简单工厂不属于 23 种设计模式，它由一个工厂类根据参数决定创建哪种产品，违反开闭原则。

## 9.11 创建型模式（二）：建造者与原型

建造者模式将一个复杂对象的构建与它的表示分离，使同样的构建过程可以创建不同的表示，包含产品、抽象建造者、具体建造者和指挥者四个角色，指挥者负责控制构建的顺序，适用于创建步骤固定但各步骤细节不同的复杂对象。原型模式通过复制已有的实例来创建新对象，而不是通过 new 创建，适用于创建对象成本较高或者需要保存对象状态副本的场合，实现的关键是克隆方法，分为浅拷贝和深拷贝：浅拷贝只复制对象本身，引用类型的成员仍然共享同一个对象；深拷贝同时复制引用类型的成员对象，副本与原对象完全独立。创建型模式的共同点是把对象的创建与使用分离，降低系统耦合。

## 9.12 结构型模式（一）：适配器、桥接、组合与装饰器

适配器模式把一个类的接口转换成客户端期望的另一种接口，使原本由于接口不兼容而不能一起工作的类可以一起工作，分为类适配器和对象适配器，类适配器通过继承实现，对象适配器通过组合实现。桥接模式把抽象部分与实现部分分离，使它们可以独立变化，用组合代替继承来避免类的数量爆炸，如不同形状与不同颜色的组合。组合模式把对象组合成树形结构表示部分整体层次，使客户对单个对象和组合对象的使用具有一致性，适用于文件系统、组织结构等树形场景，包含组件、叶子和容器三个角色。装饰器模式动态地给对象添加额外的职责，比继承更灵活，装饰器与被装饰对象实现相同的接口，并持有被装饰对象的引用，可以层层嵌套，如 Java 的 IO 流。

## 9.13 结构型模式（二）：外观、享元与代理

外观模式为子系统中的一组接口提供一个统一的高层接口，使子系统更易使用，降低客户端与子系统的耦合，符合迪米特法则，但不限制客户端直接访问子系统。享元模式运用共享技术有效地支持大量细粒度对象，把对象的状态分为内部状态和外部状态，内部状态可共享、不随环境变化，外部状态不可共享、由客户端传入，用来减少内存占用，如围棋棋子、字符对象、对象池。代理模式为其他对象提供一个代理以控制对该对象的访问，常见的有远程代理、虚代理、保护代理和智能引用代理：远程代理代表位于不同地址空间的对象，虚代理按需创建开销大的对象，保护代理控制访问权限，智能引用代理增加额外操作。代理与被代理对象实现相同的接口。装饰器侧重增加职责，代理侧重控制访问。

## 9.14 行为型模式（一）：责任链、命令、解释器、迭代器、中介者与备忘录

责任链模式使多个对象都有机会处理请求，从而避免请求发送者与接收者之间的耦合，把这些对象连成一条链，沿链传递请求直到被处理，如审批流程、异常处理。命令模式把请求封装成对象，从而可以用不同的请求参数化客户，支持请求排队、记录日志和撤销操作。解释器模式给定一种语言，定义它的文法表示，并定义一个解释器来解释语言中的句子，适用于简单文法如正则表达式。迭代器模式提供一种方法顺序访问聚合对象中的各个元素，而不暴露其内部表示，支持多种遍历方式。中介者模式用一个中介对象封装一系列对象之间的交互，使各对象不需要显式地相互引用，把多对多关系变成一对多，降低耦合，如聊天室、机场塔台。备忘录模式在不破坏封装性的前提下捕获并保存对象的内部状态，以便以后恢复，典型应用是撤销和快照，包含原发器、备忘录和负责人三个角色。

## 9.15 行为型模式（二）：观察者、状态、策略、模板方法与访问者

观察者模式定义对象间的一对多依赖，当一个对象的状态发生改变时，所有依赖它的对象都得到通知并被自动更新，又称发布订阅模式，包含主题和观察者，如事件监听、消息订阅。状态模式允许一个对象在其内部状态改变时改变它的行为，把与状态相关的行为分散到各个状态类中，消除庞大的条件分支语句，如订单状态、TCP 连接状态。策略模式定义一系列算法，把它们一个个封装起来，并使它们可以相互替换，让算法的变化独立于使用它的客户，如排序算法、支付方式、折扣策略。策略模式由客户端选择策略，而状态模式的状态转换由状态对象自身或上下文完成。模板方法模式在父类中定义算法的骨架，把某些步骤延迟到子类中实现，使子类可以不改变算法结构而重新定义某些特定步骤，是基于继承的代码复用。访问者模式表示一个作用于某对象结构中各元素的操作，可以在不改变各元素类的前提下定义作用于这些元素的新操作，适用于对象结构稳定而操作经常变化的场景，但增加新的元素类很困难。
