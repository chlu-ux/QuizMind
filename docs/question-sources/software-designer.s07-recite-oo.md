# 软件设计师（中级）基础知识速记（面向对象技术）

## 7.1 面向对象基础

**一、6 大基本概念**

| 概念 | 含义 |
|---|---|
| 对象 | 基本运行时实体，**封装属性（数据）+ 方法（操作）**；由对象名、属性、方法组成 |
| 消息 | 对象间通信的构造；发送者不需知道接收者如何响应 |
| 类 | 一组相似对象的抽象；对象是类的**实例** |
| 继承 | 基于已有类创建新类，**解决代码复用**；分单继承、多继承 |
| 多态 | 同一消息不同对象产生不同结果 |
| 绑定 | 把过程调用与执行代码结合 |

**二、多态的两种表现**

- **方法重载（Overload）**：同一个类中，方法名相同、参数表不同。
- **方法覆盖 / 重写（Override）**：子类与父类同名同参，子类覆盖父类。

**三、多态的 4 种形式**

| 形式 | 说明 |
|---|---|
| 参数多态 | 最纯的多态（泛型） |
| 包含多态 | 子类型化（子类替换父类） |
| 过载多态 | 同一名字在不同上下文含义不同 |
| 强制多态 | 编译时强行类型转换 |

**四、绑定**

- **静态绑定（早绑定）**：编译时确定（如重载）。
- **动态绑定（晚绑定）**：运行时确定（如重写）。

> ⚠ 多态实现条件：**继承 + 子类重写父类方法 + 父类引用调用**。

**五、OOA 5 活动（顺序必背）**

认定对象 → 组织对象 → 描述对象间相互作用 → 确定对象操作 → 定义对象内部信息。

**六、OOD 5 活动**

识别类及对象 → 定义属性 → 定义服务 → 识别关系 → 识别包。

**七、OOD 7 大设计原则**

| 原则 | 含义 |
|---|---|
| 单一责任原则 | 一个类只有一个引起变化的原因（只做一种事） |
| 开放 - 封闭原则 | 对扩展开放，对修改封闭 |
| 里氏替换原则 | 子类必须能替换父类（is-a 关系） |
| 依赖倒置原则 | 高层不依赖低层，都依赖抽象 |
| 接口分离原则 | 不强迫客户依赖不用的方法 |
| 共同封闭原则 | 一个包中类对同一变化共同封闭 |
| 共同重用原则 | 重用包中一个类就要重用包中所有类 |

**八、OO 测试 4 层**

| 层次 | 对应传统测试 |
|---|---|
| 算法层 | 测每个方法 ≈ 单元测试 |
| 类层 | 测类内方法间相互作用（OO 特有） |
| 模板层 | 测一组协同类 ≈ 集成测试 |
| 系统层 | 组装成完整系统 |

## 7.2 UML

**一、3 种构造块**：事物、关系、图。

**二、4 种事物**

| 事物 | 类型 |
|---|---|
| 结构事物（名词，静态） | 类、接口、协作、用例、主动类、构件、制品、结点 |
| 行为事物（动词，动态） | 交互、状态机、活动 |
| 分组事物（组织） | **包（Package）** |
| 注释事物（解释） | **注解（Note）** |

**三、4 种关系**

| 关系 | 图形 | 含义 |
|---|---|---|
| 依赖 | 虚线箭头 | 一个事物变化影响另一个（“用”） |
| 关联 | 实线 | 结构关系，对象间连接 |
| 聚合 | 空心菱形实线 | 整体 - 部分，**部分可独立于整体**（弱拥有） |
| 组合 | 实心菱形实线 | 整体 - 部分，**同生命周期**（强拥有） |
| 泛化 | 空心三角实线 | 继承（特殊 / 一般） |
| 实现 | 空心三角虚线 | 接口与实现类之间 |

> ⚠ 组合：整体没了部分也没（如公司和部门）；聚合：整体没了部分还在（如班级和学生）。网店与商品 → 组合；购物车与商品 → 聚合。

**四、常用 UML 图**

| 图 | 作用 |
|---|---|
| 类图 | 静态视图，类 / 接口 / 关系（最常见） |
| 对象图 | 某一时刻对象实例的静态快照 |
| 用例图 | 参与者、用例、包含 / 扩展关系 |
| 序列图（时序图） | 对象间消息，**强调时间顺序** |
| 通信图（协作图） | 对象间链接与消息，**强调对象结构** |
| 状态图 | 一个对象的状态转换、事件、活动 |
| 活动图 | 从一个活动到另一个活动的流程（特殊状态图） |
| 构件图 | 构件间组织和依赖 |
| 部署图 | 物理结点及构件配置 |
| 包图 | 模型组织单元及依赖 |

## 7.3 设计模式

**一、三大类（必背）**

- **创建型（5）**：对象创建。
- **结构型（7）**：类和对象组合。
- **行为型（11）**：类和对象通信、职责分配。

**二、创建型 5 个**

| 模式 | 意图关键词 |
|---|---|
| Singleton 单例 | 一个类只有**一个实例**，提供全局访问点 |
| Factory Method 工厂方法 | 定义创建对象接口，**让子类决定实例化哪个类** |
| Abstract Factory 抽象工厂 | 创建**一系列相关 / 相互依赖**对象的接口 |
| Builder 生成器 | 复杂对象**构建与表示分离**，同样构建过程不同表示 |
| Prototype 原型 | **复制原型**创建新对象（clone） |

**三、结构型 7 个**

| 模式 | 意图关键词 |
|---|---|
| Adapter 适配器 | 接口转换，让不兼容类一起工作 |
| Bridge 桥接 | **抽象与实现分离**，可独立变化 |
| Composite 组合 | 树形结构表示**部分 - 整体**，统一对待单个和组合对象 |
| Decorator 装饰 | **动态**给对象加额外职责，比子类灵活 |
| Facade 外观 | 为子系统提供**统一高层接口**，简化使用 |
| Proxy 代理 | 为其他对象提供**代理控制访问** |
| Flyweight 享元 | 共享细粒度对象 |

**四、行为型 11 个**

| 模式 | 意图关键词 |
|---|---|
| Iterator 迭代器 | 顺序访问聚合元素，不暴露内部表示 |
| Observer 观察者 | **一对多依赖**，状态变化时自动通知更新 |
| Template Method 模板方法 | 定义算法骨架，**子类延迟实现某些步骤** |
| Command 命令 | **把请求封装成对象**，可排队、日志、撤销 |
| Chain of Responsibility 责任链 | 多个对象处理请求，**连成链传递**直到有对象处理 |
| State 状态 | 对象内部状态改变时**改变行为** |
| Strategy 策略 | 封装一系列算法，**可互相替换**，独立于客户 |
| Memento 备忘录 | 不破坏封装下捕获并保存对象状态 |
| Mediator 中介者 | 用一个中介对象封装一系列对象交互 |
| Visitor 访问者 | 不改变类的前提下定义新操作 |
| Interpreter 解释器 | 定义语言文法，解释句子 |
