# 软件设计师（中级）强化训练（难点突破）

## D3.1 难点：PV 操作的设计与易错点

PV 操作解题步骤：先判断进程之间是互斥还是同步关系。互斥用一个初值为 1 的信号量，P 放在临界区之前，V 放在临界区之后；同步关系对每个“先后约束”设一个初值为 0 的信号量，前驱进程完成后 V，后继进程开始前 P。P、V 必须成对出现，且 P 操作的顺序不能随意交换：生产者消费者问题中，生产者必须先 P(empty) 再 P(mutex)，如果颠倒为先 P(mutex) 再 P(empty)，缓冲区满时生产者持有 mutex 并阻塞，消费者无法获得 mutex 去取走产品，造成死锁。读者写者问题（读者优先）：用计数器 readcount 记录读者数，第一个读者执行 P(wmutex)，最后一个读者离开时执行 V(wmutex)，readcount 的修改用互斥信号量 rmutex 保护。哲学家就餐问题：5 个哲学家各拿左右叉子，若每人都先拿左叉则可能死锁，解决办法有最多允许 4 人同时就餐、奇数号哲学家先拿左叉而偶数号先拿右叉、同时拿起两把叉子（用互斥保护）。前驱图中，一个进程若有多个前驱，则开始前要对每个前驱对应的信号量各执行一次 P。信号量 S 为负数时，其绝对值表示正在等待该资源的进程数，资源信号量的初值是资源个数。

## D3.2 难点：银行家算法与安全序列

银行家算法：Need = Max - Allocation，即进程还需要的资源。安全状态是指存在一个进程执行序列，使每个进程都能获得所需的全部资源并运行完毕。检查方法：从可用资源 Available 出发，找一个 Need 不超过 Available 的进程，假设它运行完毕并释放其已分配的资源（Available 加上它的 Allocation），重复该步骤直到所有进程都完成，则存在安全序列；若找不到这样的进程，状态不安全。安全序列可能不唯一。不安全状态不一定发生死锁，但死锁一定处于不安全状态。进程提出请求 Request 时：若 Request 大于 Need，则出错；若 Request 大于 Available，则必须等待；否则先试探性分配，再做安全性检查，系统仍然安全才真正分配，否则撤销试探分配并让进程等待。注意即使可用资源足够满足请求，分配后若系统不安全，也不能分配。

## D3.3 难点：KMP 的 next 与 nextval 数组

KMP 算法中，next[j] 表示模式串第 j 个字符失配时，模式串应回退到第几个字符继续比较。下标从 1 开始时，next[1] = 0，next[2] = 1，其余按 next[j] = 第 j 个字符之前的子串中最长相等前后缀的长度加 1 计算（前后缀不包括子串本身）。例如模式串 abaabc 的 next 数组为 0、1、1、2、2、3。求 next 的口诀：看前一个字符之前的串，求最长相等的前缀和后缀的长度，再加 1。失配时，主串指针不动，模式串指针 j 变为 next[j]，若 next[j] 为 0，则主串和模式串指针都后移一位。nextval 是对 next 的优化，用来避免失配后又用相同字符比较：若 p[j] 等于 p[next[j]]，则 nextval[j] = nextval[next[j]]，否则 nextval[j] = next[j]，nextval[1] = 0。模式串 aaaab 的 next 数组为 0、1、2、3、4，nextval 数组为 0、0、0、0、4。KMP 的时间复杂度为 O(n + m)，主串指针不回溯。

## D3.4 难点：AVL 旋转、堆调整与 B 树性质

平衡二叉树（AVL）插入后若某结点失衡，按失衡类型旋转：LL 型（在左子树的左子树插入）右旋，RR 型（在右子树的右子树插入）左旋，LR 型（在左子树的右子树插入）先对左孩子左旋再对失衡结点右旋，RL 型（在右子树的左子树插入）先对右孩子右旋再对失衡结点左旋。依次插入 10、20、30 时在结点 10 处出现 RR 型失衡，左旋后 20 成为根。依次插入 1 到 7，经过 4 次左旋，最终得到以 4 为根的完全平衡二叉树，先序序列为 4、2、1、3、6、5、7。建堆的方法：从最后一个非叶结点（从 1 开始编号，下标 ⌊n/2⌋）开始，自下而上依次向下调整，时间复杂度为 O(n)；逐个插入建堆的时间复杂度为 O(n log n)。小顶堆的堆顶是最小值，堆排序每次取出堆顶后用最后一个元素补到堆顶再向下调整。m 阶 B 树：每个结点最多有 m 棵子树、m - 1 个关键字；除根结点外，非叶结点至少有 ⌈m/2⌉ 棵子树；根结点若不是叶子，至少有 2 棵子树；所有叶子结点在同一层。3 阶 B 树每个结点最多 2 个关键字，依次插入 1 到 7，最终根结点为 4，树高为 3。

## D3.5 难点：Prim、Kruskal 与 Dijkstra 的执行过程

最小生成树：Prim 算法从某个顶点出发，每次选取连接已选顶点集合与未选顶点集合的权值最小的边，把新顶点并入；Kruskal 算法把所有边按权值从小到大排序，依次选取，若加入后形成回路则舍弃，判断回路通常用并查集；两种算法得到的生成树总权值相同；边权互不相同时最小生成树唯一，边权有相同时可能有多棵。n 个顶点的生成树恰好有 n - 1 条边。Dijkstra 算法求单源最短路径：每一轮选出当前距离源点最近且尚未确定的顶点，用它去松弛（更新）邻接点的距离，不能有负权边。最短路径不一定经过最少的边，而是边权之和最小。拓扑排序的结果往往不唯一：每一步可以选择任意一个入度为 0 的顶点。例如图中 1→2、1→3、2→4、3→4 有 2 种拓扑序列，1→3、2→3、3→4、3→5 有 4 种拓扑序列。

## D3.6 难点：范式判定、无损连接与保持函数依赖

范式判定步骤：先求候选键，再检查非主属性。2NF 要求不存在非主属性对候选键的部分依赖；3NF 要求不存在非主属性对候选键的传递依赖；BCNF 要求每个非平凡函数依赖的决定因素都包含候选键（即是超键）。3NF 与 BCNF 的区别：3NF 允许决定因素不是超键，只要被决定的属性是主属性；因此 BCNF 一定是 3NF，反之不一定。任何二元关系模式一定属于 BCNF。无损连接的判定（把 R 分解成 R1 和 R2）：当且仅当 R1 与 R2 的公共属性能函数决定 R1 - R2 或 R2 - R1 时，分解是无损的。保持函数依赖要求原关系的每个函数依赖，都能由分解后各关系上的函数依赖推出。分解到 3NF 总能做到既无损连接又保持函数依赖，分解到 BCNF 总能做到无损连接，但不一定保持函数依赖。求最小函数依赖集的步骤：把右部拆成单个属性；去掉冗余的函数依赖；去掉左部多余的属性。

## D3.7 难点：冲突可串行化与两段锁协议

并发调度的正确性标准是可串行化。冲突操作是指属于不同事务、访问同一数据项、且至少有一个是写操作的两个操作；读与读不冲突，同一事务内的操作不算冲突。冲突可串行化的判定：画优先图（前驱图），每个事务是一个结点，若事务 Ti 的操作与事务 Tj 的后续操作冲突，则画一条从 Ti 到 Tj 的边；优先图无环则调度是冲突可串行化的，等价的串行顺序就是图的拓扑序，有环则不是。两段锁协议要求每个事务分为加锁阶段和解锁阶段，一旦释放了任何一个锁，就不能再申请新的锁；遵守两段锁协议的调度一定是可串行化的，但不能避免死锁。严格两段锁协议要求事务持有的排他锁直到事务提交或回滚才释放，可以避免级联回滚。死锁可以用等待图检测，等待图中出现环就表示发生了死锁。

## D3.8 难点：TCP 拥塞控制的窗口变化与连接管理

TCP 拥塞控制：慢启动阶段拥塞窗口 cwnd 从 1 个 MSS 开始，每经过一个往返时间（RTT）翻倍，呈指数增长，直到达到慢启动门限 ssthresh；之后进入拥塞避免阶段，每个 RTT 增加 1 个 MSS，呈线性增长；发生超时，ssthresh 设为当前 cwnd 的一半，cwnd 重置为 1，重新进行慢启动；收到 3 个重复 ACK 触发快重传，ssthresh 设为当前 cwnd 的一半，cwnd 设为新的 ssthresh（快恢复），直接进入拥塞避免。发送窗口取接收窗口 rwnd 与拥塞窗口 cwnd 中的较小者。例如 ssthresh = 8 时，各轮 cwnd 依次为 1、2、4、8、9、10。TCP 三次握手：客户端发送 SYN（序号 x），服务器回复 SYN+ACK（序号 y，确认号 x+1），客户端再发送 ACK（确认号 y+1）；SYN 报文段占用一个序号。四次挥手：主动关闭方发送 FIN，对方回复 ACK，对方数据发送完后再发送 FIN，主动关闭方回复 ACK；主动关闭方在最后进入 TIME_WAIT 状态，等待 2MSL 后才关闭。

## D3.9 难点：最长前缀匹配、VLSM 与路由协议对比

路由器转发分组采用最长前缀匹配：把目的地址与路由表各表项的掩码按位相与，结果等于该表项网络号则匹配；有多个表项匹配时，选择前缀最长（掩码最长）的表项；默认路由 0.0.0.0/0 能匹配所有地址，但前缀最短，只在没有其他表项匹配时才使用。VLSM（可变长子网掩码）：按各部门主机数需求从大到小分配子网，避免地址块重叠。例如把 192.168.1.0/24 分给需要 100、50、20 台主机的三个部门：100 台用 /25（可用 126 台），50 台用 /26（可用 62 台），20 台用 /27（可用 30 台）。RIP 是距离向量协议，以跳数为度量，最大 15 跳，16 表示不可达，周期性（约 30 秒）向邻居广播路由表，使用 UDP 520 端口，适合小型网络，存在收敛慢和路由环路问题，可用水平分割、毒性逆转等缓解。OSPF 是链路状态协议，用 Dijkstra 算法计算最短路径树，支持区域划分，收敛快，直接封装在 IP 之上。BGP 是自治系统之间的路径向量协议，基于 TCP 179 端口，注重路由策略。RIP、OSPF 属于内部网关协议，BGP 属于外部网关协议。

## D3.10 难点：Cache 地址划分与多级页表计算

主存地址位数 = log2（主存容量）。Cache 地址划分：块内地址位数 = log2（块大小）；直接映射的 Cache 块号位数 = log2（Cache 块数），标记位数 = 主存地址位数 - Cache 块号位数 - 块内地址位数；k 路组相联的组数 = Cache 块数 ÷ k，组号位数 = log2（组数），标记位数 = 主存地址位数 - 组号位数 - 块内地址位数；全相联没有块号字段，标记位数 = 主存地址位数 - 块内地址位数。多级页表：页大小为 2^k 字节，页表项大小为 e 字节，则一页能容纳的页表项数为 2^k ÷ e，每级页号的位数为 log2（2^k ÷ e）。32 位地址、页大小 4 KB、页表项 4 字节时，一级页表索引 10 位、二级页表索引 10 位、页内偏移 12 位。没有快表时，n 级页表访问一次数据需要 n + 1 次内存访问；段页式存储需要访问段表、页表和数据共 3 次内存。有快表时，快表命中率为 h，快表访问时间为 t，内存访问时间为 m，n 级页表：有效访问时间 = h × (t + m) + (1 - h) × (t + n × m + m)。

## D3.11 难点：UML 易混概念辨析

类间关系的强弱：依赖 < 关联 < 聚合 < 组合。依赖是临时的使用关系，如方法参数或局部变量；关联是长期的、结构性的关系，通常体现为成员变量；聚合表示“拥有”，部分可以脱离整体独立存在，如部门与员工；组合表示“包含”，部分随整体创建和消亡，且部分只能属于一个整体，如汽车与发动机、订单与订单项。泛化表示 is-a 的继承关系，实现表示类对接口的实现。用例之间：包含（include）是必然调用的公共子流程，由基用例指向被包含用例；扩展（extend）是满足条件才触发的可选扩展，由扩展用例指向基用例；泛化表示用例的特殊化。顺序图强调消息的时间顺序，通信图强调对象的结构和链接，二者语义等价，可以相互转换。状态图描述单个对象的状态迁移，活动图描述流程且可以表示并行。构件图表示软件构件及其依赖，部署图表示构件部署到哪些硬件节点。类图是模型的抽象结构，对象图是某一时刻实例的快照。接口只声明操作，不包含实现；抽象类可以含有部分实现，但不能被实例化。

## D3.12 难点：易混设计模式的对比

结构型：适配器（Adapter）是事后补救，让已有的、接口不兼容的类协同工作；桥接（Bridge）是事先设计，让抽象与实现独立变化；外观（Facade）简化接口，为子系统提供统一入口；装饰器（Decorator）不改变接口，动态增加职责，可以嵌套叠加多层；代理（Proxy）不改变接口，控制对对象的访问，通常只包装一层。行为型：策略（Strategy）封装可互换的算法，由客户端选择；状态（State）封装与状态相关的行为，随状态转换自动切换；模板方法用继承固定算法骨架，策略用组合替换整个算法。命令（Command）封装请求，侧重执行与撤销；备忘录（Memento）保存对象的状态，侧重恢复；观察者（Observer）是一对多的通知；中介者（Mediator）把多对多的交互集中到中介对象；责任链让请求沿链传递直到被处理。创建型：工厂方法用继承，由子类决定创建哪个产品；抽象工厂创建产品族；生成器关注分步骤构造复杂对象；原型通过克隆创建；单例保证唯一实例。享元（Flyweight）共享细粒度对象，内部状态可以共享，外部状态由客户端传入。组合（Composite）表示部分与整体的树形结构。

## D3.13 难点：逻辑覆盖用例数、等价类与边界值用例设计

设某判定为 (A > 0 且 B > 0) 或 C > 0，含 3 个简单条件。语句覆盖和判定覆盖都只关注语句或判定结果，判定覆盖至少需要 2 个用例，使判定结果真、假各出现一次；条件覆盖要求每个简单条件的真、假取值都出现至少一次，最少 2 个用例即可，但它不一定保证判定结果真假都出现；条件组合覆盖要求所有条件取值的组合都出现，3 个条件需要 2^3 = 8 个组合；修正条件判定覆盖（MC/DC）要求每个条件都能独立地影响判定结果，n 个条件至少需要 n + 1 个测试用例，最多 2n 个。等价类划分设计用例的原则：设计一个新用例，尽可能多地覆盖尚未覆盖的有效等价类，直到所有有效等价类被覆盖；对每个无效等价类设计一个单独的用例，且该用例只含这一个无效值。边界值分析：n 个独立变量时，基本边界值分析需要 4n + 1 个用例，健壮性边界值分析需要 6n + 1 个用例，最坏情况边界值分析需要 5^n 个用例。判定表有 n 个条件时，完整的规则数为 2^n，合并相同动作的规则后可以化简。

## D3.14 难点：AOE 网的关键路径、时差与多关键路径

AOE 网中，事件 vj 的最早发生时间 ve(j) 等于从源点到 vj 的最长路径长度，按拓扑序递推：ve(j) = max{ve(i) + 活动 <i, j> 的时间}。事件的最迟发生时间 vl(i) 从汇点反向递推：vl(i) = min{vl(j) - 活动 <i, j> 的时间}，汇点的 vl 等于它的 ve。活动 <i, j> 的最早开始时间 e = ve(i)，最迟开始时间 l = vl(j) - 活动时间，时差 = l - e。时差为 0 的活动是关键活动，关键活动构成关键路径，关键路径的长度就是完成整个工程的最短工期。关键路径可能不止一条；当存在多条关键路径时，只缩短其中一条路径上的关键活动，工期不会缩短，要同时缩短所有关键路径共有的关键活动，或在每条关键路径上各缩短一个活动，才能缩短工期。缩短关键活动的时间可能使原来的非关键路径变成新的关键路径，所以缩短的幅度受到其他路径的限制。非关键活动在时差范围内延期，不影响整个工期。

## D3.15 难点：容易混淆的概念对照

内部碎片是分配给进程的内存块内部没有被使用的部分，固定分区和页式管理会产生内部碎片；外部碎片是分区之间无法利用的小空闲块，可变分区和段式管理会产生外部碎片，可以用紧凑（移动内存中的程序）来解决。逻辑地址是程序中使用的地址，物理地址是内存单元的实际地址，由地址变换机构（MMU）把逻辑地址转换为物理地址。并发是多个任务在同一时间段内交替执行，并行是多个任务在同一时刻同时执行。互斥是对临界资源的排他访问，同步是进程之间按一定的顺序协调执行。验证（Verification）检查是否正确地构造了产品，即是否符合规格说明；确认（Validation）检查是否构造了正确的产品，即是否满足用户需求。重载是同一个类中方法名相同而参数列表不同，在编译时确定调用哪一个，属于静态绑定；重写是子类重新定义父类中同签名的方法，运行时按对象的实际类型调用，属于动态绑定。超键是能唯一标识元组的属性集，候选键是最小的超键，主键是从候选键中选定的一个，外键是引用其他关系主键的属性。病毒需要寄生在宿主文件上；蠕虫不需要宿主，利用网络漏洞自我复制传播；木马伪装成正常程序，不自我复制。防火墙按规则控制网络访问；入侵检测系统（IDS）发现攻击并报警，不主动阻断；入侵防御系统（IPS）在检测的同时可以主动阻断攻击。
