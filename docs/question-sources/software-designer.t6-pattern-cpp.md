# 软件设计师（中级）下午题六（设计模式代码填空·C++）

## T6.1 C++ 的类、虚函数与继承写法

C++ 版本的题目除了模式本身，还要写对指针、虚函数和继承的语法。

C++ 没有 interface 关键字，抽象类用至少含一个纯虚函数的类表示。纯虚函数的写法是 virtual 返回类型 函数名(参数) = 0，含有纯虚函数的类不能创建对象。
C++ 的继承写成 class 子类 : public 基类，C++ 支持多继承。
C++ 中基类的析构函数要声明为 virtual，这样通过基类指针 delete 子类对象时才会调用子类的析构函数。
C++ 的多态必须通过基类的指针或引用调用虚函数才能实现。
C++11 起可以在子类重写的虚函数声明后加 override，让编译器检查是否真的重写了基类的虚函数。
C++ 中 new 创建的对象要用 delete 释放，通过指针调用成员用 ->，通过对象或引用调用用 .，访问静态成员和类作用域用 ::。
头文件里要写 #include <iostream>，使用 using namespace std; 后可以直接写 cout 和 string。

## T6.2 单例（Singleton）

**意图**：保证一个类只有一个实例，并提供一个全局访问点。常用于配置管理器、线程池、日志对象。

**类图角色**：只有一个类，它有一个私有的静态属性 instance、一个私有的构造函数和一个公有的静态方法 getInstance()。

**C++ 写法**：C++ 里用 static 声明类的静态成员，指向唯一实例的指针也是静态成员。
C++ 的静态成员变量必须在类外定义并初始化，写成「类型 类名::变量名 = 初值;」，例如 Config* Config::instance = nullptr;。
静态成员函数用 Config::getInstance() 调用，返回指向唯一实例的指针。
懒汉式：第一次调用时才用 new 创建唯一的实例，之后直接返回已有的实例。

**常见填空**：private / static 关键字；new Config()；类外初始化 Config::instance。

## T6.3 工厂方法（Factory Method）

**意图**：定义一个创建对象的接口，让子类决定实例化哪个类，把对象的创建延迟到子类。

**类图角色**：抽象产品 Product，具体产品 ConcreteProduct，抽象工厂（创建者）Creator，具体工厂 ConcreteCreator。抽象工厂里声明工厂方法，具体工厂重写它。

**C++ 写法**：C++ 里抽象类通过纯虚函数实现，写法是 virtual 返回类型 函数名() = 0。
具体工厂重写工厂方法，返回对应的具体产品对象，用 new 创建，返回指针；调用方用完后要 delete。
抽象产品和抽象工厂都要有虚析构函数。
工厂方法的返回类型是抽象产品，子类重写它并返回具体产品。

**常见填空**：工厂方法的返回类型（抽象产品）；createProduct() 的调用；new ConcreteProduct()。

## T6.4 抽象工厂（Abstract Factory）

**意图**：提供一个创建一系列相关或相互依赖对象的接口，而无需指定它们的具体类。适用于产品族，例如 Windows 风格和 Mac 风格的界面组件。

**类图角色**：抽象工厂 AbstractFactory，具体工厂 ConcreteFactory；每种产品有一个抽象产品（AbstractProductA、AbstractProductB），以及各系列的具体产品。

**C++ 写法**：C++ 里抽象类通过纯虚函数实现，写法是 virtual 返回类型 函数名() = 0。
创建方法返回抽象产品的指针，在具体工厂里用 new 创建对应的具体产品。客户端的参数用抽象工厂的指针。
一个具体工厂创建同一个产品族的全部产品，保证风格一致。客户端只依赖抽象工厂和抽象产品，不依赖具体类，更换产品族只需要换一个具体工厂。

**常见填空**：创建方法的返回类型；new 具体产品；客户端的构造函数参数类型（抽象工厂）。
**和工厂方法的区别**：工厂方法只有一个产品等级结构，抽象工厂有多个产品等级结构，一个具体工厂负责创建整个产品族。

## T6.5 建造者（Builder）

**意图**：将一个复杂对象的构建与它的表示分离，使同样的构建过程可以创建不同的表示。

**类图角色**：产品 Product，抽象建造者 Builder（声明各个构建步骤和 getResult），具体建造者 ConcreteBuilder，指挥者 Director（控制构建顺序）。

**C++ 写法**：C++ 的继承写成 class 子类 : public 基类。指挥者持有抽象建造者的指针，通过 -> 调用 buildPartA()、buildPartB() 等步骤，最后用 getResult() 取得产品。
指挥者按固定的顺序调用建造者的各个步骤，最后取得产品。

**常见填空**：指挥者构造函数的参数类型（抽象建造者）；步骤方法名；getResult()。

## T6.6 原型（Prototype）

**意图**：用原型实例指定要创建对象的种类，并通过复制这个原型来创建新的对象。适用于创建对象成本较高，或需要保存对象状态副本的场合。

**类图角色**：抽象原型 Prototype（声明 clone 方法），具体原型 ConcretePrototype（实现 clone）。

**C++ 写法**：C++ 的继承写成 class 子类 : public 基类。
C++ 的原型模式用拷贝构造函数实现克隆，写成 new 类名(*this)。抽象原型的 clone 返回抽象原型的指针，声明为纯虚函数。
原型的克隆方法返回的是原对象的副本。重写 clone 时可以把返回类型改成本类，调用者不用强制转换。

**常见填空**：clone 的返回类型；new Resume(*this)。

## T6.7 适配器（Adapter）

**意图**：把一个类的接口转换成客户端期望的另一种接口，使原本由于接口不兼容而不能一起工作的类可以一起工作。

**类图角色**：目标接口 Target，被适配者 Adaptee（已有的类，接口不符合要求），适配器 Adapter，客户端 Client。对象适配器通过组合持有被适配者；类适配器通过继承被适配者实现。

**C++ 写法**：C++ 里适配器继承目标类，用 : public 目标类，并保存被适配者的指针；转发调用时用 -> 调用被适配者的成员函数。
客户端只依赖目标接口，不知道被适配者的存在，所以客户端的参数类型是目标类的指针。类适配器用多继承：同时继承目标类和被适配者类。
适配器在目标接口的方法里，把调用转发给被适配者已有的方法。

**常见填空**：被适配者的类名；转发调用的方法名；客户端参数类型。

## T6.8 桥接（Bridge）

**意图**：把抽象部分与实现部分分离，使它们可以独立变化。用组合代替继承，避免形状×颜色这样的多维度导致子类爆炸。

**类图角色**：抽象部分 Abstraction（持有实现部分的引用），扩展抽象部分 RefinedAbstraction，实现部分接口 Implementor，具体实现部分 ConcreteImplementor。

**C++ 写法**：抽象部分的成员是实现部分接口的指针，同样是桥接模式中抽象部分持有实现部分的抽象接口，两者通过组合连接。
C++ 的子类在构造函数的初始化列表里调用基类的构造函数，写法是 基类名(参数)。
C++ 通过指针调用成员函数用 ->，通过对象或引用调用用 .。
桥接模式中抽象部分持有实现部分的抽象接口，两者通过组合连接。这个持有的引用就是「桥」。

**常见填空**：抽象部分里实现部分的类型；初始化列表；通过指针调用实现部分的方法。

## T6.9 组合（Composite）

**意图**：将对象组合成树形结构以表示「部分—整体」的层次，使客户端对单个对象和组合对象的使用具有一致性。

**类图角色**：抽象构件 Component，叶子 Leaf，组合节点 Composite（持有子构件列表，提供 add、remove）。

**C++ 写法**：C++ 的 vector 在末尾追加元素用 push_back。子节点列表是 vector<Component*>，保存抽象构件的指针，因为 Component 是抽象类，不能按值保存。
遍历时用 children[i]->show() 调用，这是通过基类指针的多态调用。
组合节点保存的子节点是抽象构件类型，既可以是叶子也可以是组合节点，例如 List<Component>。
组合节点通过遍历子节点并调用它们的同名方法实现递归。

**常见填空**：列表的元素类型；push_back；递归调用的方法名。

## T6.10 装饰器（Decorator）

**意图**：动态地给对象添加额外的职责。比继承更灵活：不同的装饰器可以任意组合、层层嵌套，而不用为每种组合写一个子类。

**类图角色**：抽象构件 Component，具体构件 ConcreteComponent，抽象装饰器 Decorator（实现 Component 并持有一个 Component），具体装饰器 ConcreteDecorator。

**C++ 写法**：装饰器类持有的是抽象构件的指针 Component*。
C++ 的子类在构造函数的初始化列表里调用基类的构造函数，写法是 基类名(参数)，具体装饰器要把被装饰对象传给直接父类（抽象装饰器）。
调用被装饰对象的方法用 beverage->cost()。
装饰器和被装饰对象实现同一个抽象构件接口，并且持有一个抽象构件的引用。
装饰器在自己的方法里先调用被装饰对象的方法，再附加自己的功能，例如 beverage.cost() + 5。

**常见填空**：装饰器持有的类型；抽象装饰器的构造函数调用；对被装饰对象的方法调用。

## T6.11 外观（Facade）

**意图**：为子系统中的一组接口提供一个一致的高层接口，使子系统更容易使用，减少客户端与子系统的耦合。

**类图角色**：外观 Facade，各个子系统类 SubsystemA、SubsystemB 等。客户端只和外观打交道。

**C++ 写法**：外观类的成员是各子系统对象的指针，在构造函数里用 new 创建，在析构函数里 delete。
C++ 通过指针调用成员函数用 ->，通过对象或引用调用用 .。析构函数的名字是 ~ 加类名，例如 ~HomeTheater()。
外观模式为一组子系统提供统一的高层接口，外观类持有各个子系统对象。

**常见填空**：子系统的类名；子系统的方法名；new 子系统；析构函数。

## T6.12 代理（Proxy）

**意图**：为其他对象提供一种代理，以控制对这个对象的访问。常见的有虚拟代理（延迟加载）、保护代理（权限检查）、远程代理。

**类图角色**：抽象主题 Subject，真实主题 RealSubject，代理 Proxy。

**C++ 写法**：C++ 里用 new 创建的对象要用 delete 释放，代理类的析构函数要释放它创建的真实对象。
代理持有真实主题的指针，初始化为 nullptr，第一次调用时才 new。
代理类和真实主题实现同一个抽象主题接口，代理持有真实主题的引用。
虚拟代理在第一次使用时才创建真实对象，之后复用同一个对象，写成 if (real == null) { real = new RealImage(file); }。

**常见填空**：真实主题的类型；new RealImage(file)；转发调用的方法名；delete。

## T6.13 策略（Strategy）

**意图**：定义一系列算法，把每个算法封装起来，并使它们可以相互替换。让算法的变化独立于使用算法的客户。

**类图角色**：上下文 Context，抽象策略 Strategy，具体策略 ConcreteStrategy。

**C++ 写法**：C++ 的继承写成 class 子类 : public 基类。上下文的成员是抽象策略的指针，调用时写 strategy->calculate(price)。
策略模式中每个具体策略都实现同一个抽象策略接口，上下文持有抽象策略的引用。
上下文把算法的执行委托给当前持有的策略对象，运行时可以更换策略，通过 setStrategy 设置。

**常见填空**：上下文里策略的类型（抽象策略）；委托调用的方法名。
**和状态模式的区别**：策略由客户端选择并设置，策略之间互不知晓；状态由状态对象自己负责切换到下一个状态。

## T6.14 观察者（Observer）

**意图**：定义对象间的一对多依赖，当一个对象的状态改变时，所有依赖它的对象都得到通知并自动更新。

**类图角色**：主题 Subject（维护观察者列表，提供 attach、detach、notify），抽象观察者 Observer（声明 update），具体观察者 ConcreteObserver。

**C++ 写法**：C++ 里抽象类通过纯虚函数实现，写法是 virtual 返回类型 函数名() = 0，观察者的 update 就是纯虚函数。
主题保存观察者的指针列表 vector<Observer*>，遍历时用 observers[i]->update(temp)。
主题（Subject）维护一个抽象观察者的列表，状态改变时遍历列表逐个通知。
状态改变时，主题遍历观察者列表，调用每个观察者的 update 方法。

**常见填空**：列表的元素类型（抽象观察者）；push_back；update；virtual。

## T6.15 模板方法（Template Method）

**意图**：在父类中定义算法的骨架，把某些步骤延迟到子类实现，使子类可以不改变算法结构而重定义某些步骤。

**类图角色**：抽象类 AbstractClass（模板方法 + 抽象步骤 + 具体步骤），具体类 ConcreteClass（实现抽象步骤）。

**C++ 写法**：模板方法在父类中按固定顺序调用各个步骤，其中抽象步骤由子类实现，直接写 brew()，由虚函数机制调用子类的版本。
C++ 里抽象类通过纯虚函数实现，写法是 virtual 返回类型 函数名() = 0。C++ 的继承写成 class 子类 : public 基类。

**常见填空**：virtual；步骤调用。

## T6.16 状态（State）

**意图**：允许一个对象在其内部状态改变时改变它的行为，对象看起来好像修改了它的类。

**类图角色**：上下文 Context（持有当前状态），抽象状态 State，具体状态 ConcreteState。

**C++ 写法**：C++ 里两个类相互引用时，要先对其中一个做前向声明，写成 class 类名;，例如 State 的方法用到了 Order 指针，就在前面写 class Order;。
在成员函数里 this 就是指向当前对象的指针，把 this 传给状态的 handle 方法。
状态模式的上下文持有抽象状态的引用，把行为委托给当前状态对象，调用 state.handle(this)。
状态模式中状态转换由具体状态类完成：处理完后调用上下文的 setState 切换到下一个状态。

**常见填空**：上下文里状态的类型；handle；new 下一个状态；class Order; 前向声明；this。

## T6.17 命令（Command）

**意图**：把请求封装成对象，从而可以用不同的请求对客户进行参数化，对请求排队、记录日志，以及支持撤销。

**类图角色**：抽象命令 Command，具体命令 ConcreteCommand（持有接收者），接收者 Receiver，调用者 Invoker。

**C++ 写法**：具体命令的成员是接收者的指针 Receiver*，构造函数用接收者指针初始化，execute 中用 -> 调用接收者的方法，例如 light->on()。调用者持有 Command* 并调用 command->execute()。
命令模式把请求封装成对象：抽象命令声明 execute 方法，具体命令持有接收者并在 execute 中调用它的方法。
命令模式的调用者只持有抽象命令，通过 execute 触发请求，不依赖具体接收者。

**常见填空**：接收者的方法名；调用者持有的类型（抽象命令）；execute。

## T6.18 责任链（Chain of Responsibility）

**意图**：使多个对象都有机会处理请求，从而避免请求的发送者和接收者之间的耦合。把这些对象连成一条链，沿着链传递请求，直到有一个对象处理它。

**类图角色**：抽象处理者 Handler（持有后继，声明 handle），具体处理者 ConcreteHandler。

**C++ 写法**：C++ 的继承写成 class 子类 : public 基类。后继是 Handler* 指针，初始化为 nullptr，转发时用 next->handle(days)。
责任链中每个处理者持有指向下一个抽象处理者的引用，处理不了的请求转发给后继，写成 next.handle(days)。

**常见填空**：后继的类型（抽象处理者）；转发调用 next->handle(...)；权限判断的条件。

## T6.19 迭代器（Iterator）

**意图**：提供一种方法顺序访问聚合对象中的各个元素，而又不暴露该对象的内部表示。

**类图角色**：抽象聚合 Aggregate（声明 createIterator），具体聚合，抽象迭代器 Iterator（hasNext、next），具体迭代器。

**C++ 写法**：C++ 的继承写成 class 子类 : public 基类。具体迭代器可以写成聚合类的嵌套类，持有聚合对象的指针，getIterator 里写成 new NameIterator(this)。
vector 的元素个数是 size()。
迭代器模式把遍历的职责从聚合对象中分离出来，聚合对象的 getIterator 方法返回一个迭代器对象。
迭代器的 next 方法返回当前元素，并把游标移到下一个元素，所以用 index++。

**常见填空**：index++；new NameIterator(this)。

## T6.20 访问者（Visitor）

**意图**：表示一个作用于某对象结构中的各元素的操作。可以在不改变各元素的类的前提下定义作用于这些元素的新操作。

**类图角色**：抽象访问者 Visitor（对每种元素声明一个 visit 方法），具体访问者，抽象元素 Element（声明 accept），具体元素。

**C++ 写法**：accept 的参数是抽象访问者的指针 Visitor*。元素和访问者相互引用，要用前向声明 class Book; 在前面声明，accept 的实现写在类外。
在 accept 中把 this 传给 visit，通过 fruit->price 访问元素的数据。
访问者模式的 accept 方法调用访问者的 visit 方法，并把元素自己（this）作为参数传入，称为双分派。
访问者通过 visit 方法的参数访问元素的数据，对不同类型的元素做不同的处理。

**常见填空**：visit(this) 里的 this；accept 的参数类型；visit 方法里访问元素的数据。

## T6.21 备忘录（Memento）

**意图**：在不破坏封装性的前提下，捕获一个对象的内部状态，并在该对象之外保存这个状态，以后可以把对象恢复到原先保存的状态。

**类图角色**：发起人 Originator（创建和恢复备忘录），备忘录 Memento（保存状态），管理者 Caretaker（保管备忘录）。

**C++ 写法**：发起人的 save 用 new Memento(text) 创建备忘录并返回指针，restore 接收 Memento* 并通过 m->getText() 取出状态。
管理者保存的是 Memento* 指针，用完要 delete。
备忘录模式中发起人创建备忘录保存自己的内部状态，需要时用备忘录恢复。发起人的 save 方法返回 new Memento(text)，restore 方法的参数是 Memento。
备忘录模式的管理者只负责保存和提供备忘录，不检查也不修改备忘录的内容。管理者的 push 存入，pop 取出。

**常见填空**：new Memento(text)；restore 的参数类型；管理者的取出方法 pop；Memento*。

## T6.22 中介者（Mediator）

**意图**：用一个中介对象封装一系列对象的交互，使各对象不需要显式地互相引用，从而降低耦合，并可以独立地改变它们之间的交互。

**类图角色**：抽象中介者 Mediator，具体中介者 ConcreteMediator（持有所有同事），同事类 Colleague（持有中介者）。

**C++ 写法**：C++ 的继承写成 class 子类 : public 基类。同事类和中介者类相互引用，要用前向声明 class User; 在前面声明。
同事里持有 Mediator* 指针，通过 mediator->send(msg, this) 发送。
同事对象只持有中介者的引用，通过中介者与其他同事通信，彼此互不引用。
中介者把同事发来的消息转发给除发送者以外的其他同事，所以转发时要判断 u != from。同事发送消息写成 mediator.send(msg, this)。

**常见填空**：同事持有的类型（抽象中介者）；send / receive 的区分；排除发送者；public。
