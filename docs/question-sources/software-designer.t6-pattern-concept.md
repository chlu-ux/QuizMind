# 软件设计师（中级）下午题六（设计模式概念）

## C6.1 单例（Singleton）的概念

**意图**：保证一个类只有一个实例，并提供一个全局访问点。常用于配置管理器、线程池、日志对象。

**类图角色**：只有一个类，它有一个私有的静态属性 instance、一个私有的构造函数和一个公有的静态方法 getInstance()。

**特点与适用**：单例模式属于创建型模式，适用于系统中某个类只能有一个实例的场景，例如配置管理器、线程池和日志对象。单例的优点是严格控制实例数量、节约资源，缺点是类的职责过重，不利于单元测试。饿汉式在类加载时创建实例，线程安全；懒汉式在第一次使用时才创建实例，多线程下需要同步。实现单例需要三个要素：私有的构造函数、保存唯一实例的静态属性和公有的静态获取方法。

## C6.2 工厂方法（Factory Method）的概念

**意图**：定义一个创建对象的接口，让子类决定实例化哪个类，把对象的创建延迟到子类。

**类图角色**：抽象产品 Product，具体产品 ConcreteProduct，抽象工厂（创建者）Creator，具体工厂 ConcreteCreator。抽象工厂里声明工厂方法，具体工厂重写它。

**特点与适用**：工厂方法模式属于创建型模式，包含抽象产品、具体产品、抽象工厂和具体工厂四个角色。每增加一种产品，只需要增加一个具体产品类和对应的具体工厂类，不用修改已有代码，符合开闭原则；缺点是类的个数会成倍增加。适用于创建对象的类型在运行前无法确定、需要由子类指定创建对象的场合。简单工厂不属于 23 种设计模式，它由一个工厂类根据参数决定创建哪种产品，增加产品要修改工厂类，违反开闭原则。

## C6.3 抽象工厂（Abstract Factory）的概念

**意图**：提供一个创建一系列相关或相互依赖对象的接口，而无需指定它们的具体类。适用于产品族，例如 Windows 风格和 Mac 风格的界面组件。

**类图角色**：抽象工厂 AbstractFactory，具体工厂 ConcreteFactory；每种产品有一个抽象产品（AbstractProductA、AbstractProductB），以及各系列的具体产品。

**特点与适用**：抽象工厂模式属于创建型模式，用于创建一系列相关或相互依赖的对象，也就是「产品族」。增加新的产品族（如再增加一种界面风格）很容易，只需增加一个具体工厂和一组具体产品；但增加新的产品等级结构（如再增加一种「滚动条」组件）很困难，要修改抽象工厂和所有具体工厂。工厂方法模式针对一个产品等级结构，抽象工厂模式针对多个产品等级结构。

## C6.4 建造者（Builder）的概念

**意图**：将一个复杂对象的构建与它的表示分离，使同样的构建过程可以创建不同的表示。

**类图角色**：产品 Product，抽象建造者 Builder（声明各个构建步骤和 getResult），具体建造者 ConcreteBuilder，指挥者 Director（控制构建顺序）。

**特点与适用**：建造者模式属于创建型模式，适用于创建步骤固定、但各步骤的细节不同的复杂对象，例如组装电脑、生成不同格式的文档。指挥者负责控制构建的顺序，具体建造者负责构建各个部件，客户端通过指挥者得到完整的产品。建造者模式关注一步一步地构建一个复杂对象，抽象工厂模式关注创建一系列产品，产品直接返回。

## C6.5 原型（Prototype）的概念

**意图**：用原型实例指定要创建对象的种类，并通过复制这个原型来创建新的对象。适用于创建对象成本较高，或需要保存对象状态副本的场合。

**类图角色**：抽象原型 Prototype（声明 clone 方法），具体原型 ConcretePrototype（实现 clone）。

**特点与适用**：原型模式属于创建型模式，通过复制已有的对象来创建新对象，而不是通过 new 创建，适用于创建对象成本较高，或者需要保存对象状态副本的场合。浅拷贝只复制对象本身，引用类型的成员仍然共享同一个对象；深拷贝同时复制引用类型的成员对象，副本与原对象完全独立。

## C6.6 适配器（Adapter）的概念

**意图**：把一个类的接口转换成客户端期望的另一种接口，使原本由于接口不兼容而不能一起工作的类可以一起工作。

**类图角色**：目标接口 Target，被适配者 Adaptee（已有的类，接口不符合要求），适配器 Adapter，客户端 Client。对象适配器通过组合持有被适配者；类适配器通过继承被适配者实现。

**特点与适用**：适配器模式属于结构型模式，用于让接口不兼容的类协同工作，例如复用已有的旧类而不修改其源码。适配器分为类适配器和对象适配器：类适配器通过继承被适配者实现，对象适配器通过组合持有被适配者；对象适配器更灵活，因为它可以适配被适配者的子类。适配器模式是在系统已有类的基础上事后补救，桥接模式则是事前设计，让抽象和实现独立变化。

## C6.7 桥接（Bridge）的概念

**意图**：把抽象部分与实现部分分离，使它们可以独立变化。用组合代替继承，避免形状×颜色这样的多维度导致子类爆炸。

**类图角色**：抽象部分 Abstraction（持有实现部分的引用），扩展抽象部分 RefinedAbstraction，实现部分接口 Implementor，具体实现部分 ConcreteImplementor。

**特点与适用**：桥接模式属于结构型模式，适用于一个类有两个或多个独立变化的维度，例如形状和颜色，用桥接可以把继承关系改为组合关系，避免子类数量成倍增长（2 种形状 × 3 种颜色只需要 2+3 个类，而不是 6 个）。桥接模式遵循合成复用原则，扩展任何一个维度都不影响另一个维度。

## C6.8 组合（Composite）的概念

**意图**：将对象组合成树形结构以表示「部分—整体」的层次，使客户端对单个对象和组合对象的使用具有一致性。

**类图角色**：抽象构件 Component，叶子 Leaf，组合节点 Composite（持有子构件列表，提供 add、remove）。

**特点与适用**：组合模式属于结构型模式，适用于表示「部分—整体」的树形结构，例如文件系统中的文件和文件夹、公司的组织结构、图形的嵌套。客户端对叶子节点和组合节点一视同仁。组合模式分为透明方式和安全方式：透明方式在抽象构件里声明 add、remove 等管理子节点的方法，叶子节点对这些方法没有意义；安全方式只在组合节点里声明管理子节点的方法。

## C6.9 装饰器（Decorator）的概念

**意图**：动态地给对象添加额外的职责。比继承更灵活：不同的装饰器可以任意组合、层层嵌套，而不用为每种组合写一个子类。

**类图角色**：抽象构件 Component，具体构件 ConcreteComponent，抽象装饰器 Decorator（实现 Component 并持有一个 Component），具体装饰器 ConcreteDecorator。

**特点与适用**：装饰器模式属于结构型模式，动态地给对象增加职责，比继承更灵活：可以任意组合不同的装饰器，而不用为每种组合编写子类，避免子类爆炸。缺点是会产生很多小对象，多层装饰时调试较困难。装饰器模式强调增强对象本身的功能，代理模式强调控制对对象的访问。Java 的 IO 流中 BufferedReader 包装 FileReader 就是装饰器模式的典型应用。

## C6.10 外观（Facade）的概念

**意图**：为子系统中的一组接口提供一个一致的高层接口，使子系统更容易使用，减少客户端与子系统的耦合。

**类图角色**：外观 Facade，各个子系统类 SubsystemA、SubsystemB 等。客户端只和外观打交道。

**特点与适用**：外观模式属于结构型模式，为复杂的子系统提供一个简单的统一入口，客户端只和外观交互，从而降低客户端与子系统的耦合。外观并不限制客户端直接使用子系统，也不增加子系统的功能，只是简化调用。外观模式与适配器模式的区别：外观简化一组类的接口，适配器转换一个类的接口。

## C6.11 代理（Proxy）的概念

**意图**：为其他对象提供一种代理，以控制对这个对象的访问。常见的有虚拟代理（延迟加载）、保护代理（权限检查）、远程代理。

**类图角色**：抽象主题 Subject，真实主题 RealSubject，代理 Proxy。

**特点与适用**：代理模式属于结构型模式。常见的代理有：虚拟代理（延迟创建开销大的对象）、保护代理（检查访问权限）、远程代理（为位于另一个地址空间的对象提供本地代表）、缓存代理（缓存结果）。代理和真实对象实现同一个接口，客户端无法区分是否通过代理访问。Spring AOP 就是基于动态代理实现的。

## C6.12 策略（Strategy）的概念

**意图**：定义一系列算法，把每个算法封装起来，并使它们可以相互替换。让算法的变化独立于使用算法的客户。

**类图角色**：上下文 Context，抽象策略 Strategy，具体策略 ConcreteStrategy。

**特点与适用**：策略模式属于行为型模式，适用于一个问题有多种算法、需要在运行时选择的场合，例如不同的折扣算法、排序算法、支付方式。它用组合代替继承，消除了大量的 if-else 条件语句，增加新策略不用修改上下文，符合开闭原则；缺点是客户端必须知道所有策略的区别，并且会增加对象的数量。

## C6.13 观察者（Observer）的概念

**意图**：定义对象间的一对多依赖，当一个对象的状态改变时，所有依赖它的对象都得到通知并自动更新。

**类图角色**：主题 Subject（维护观察者列表，提供 attach、detach、notify），抽象观察者 Observer（声明 update），具体观察者 ConcreteObserver。

**特点与适用**：观察者模式属于行为型模式，也叫发布-订阅模式，用于对象间的一对多依赖，例如消息订阅、事件监听、MVC 中模型变化通知视图。主题和观察者之间是抽象耦合，二者可以独立扩展。缺点是观察者过多时通知耗时，并且要避免主题和观察者之间的循环依赖。

## C6.14 模板方法（Template Method）的概念

**意图**：在父类中定义算法的骨架，把某些步骤延迟到子类实现，使子类可以不改变算法结构而重定义某些步骤。

**类图角色**：抽象类 AbstractClass（模板方法 + 抽象步骤 + 具体步骤），具体类 ConcreteClass（实现抽象步骤）。

**特点与适用**：模板方法模式属于行为型模式，适用于多个子类有相同的算法流程、只有个别步骤不同的场合，把不变的流程放在父类，可变的步骤由子类实现，实现代码复用。它体现了「好莱坞原则」：不要给我们打电话，我们会给你打电话，即父类调用子类的方法，而不是子类调用父类。钩子方法是父类提供的、默认什么都不做的方法，子类可以选择性地重写它来控制流程。

## C6.15 状态（State）的概念

**意图**：允许一个对象在其内部状态改变时改变它的行为，对象看起来好像修改了它的类。

**类图角色**：上下文 Context（持有当前状态），抽象状态 State，具体状态 ConcreteState。

**特点与适用**：状态模式属于行为型模式，适用于对象的行为取决于它的状态，并且状态之间会转换的场合，例如订单的新建、已付款、已发货，电梯的运行与停止。它把每种状态的行为封装到独立的状态类里，消除了庞大的 if-else 或 switch 条件分支。状态模式与策略模式的结构相似：策略由客户端选择并相互独立，状态则由状态对象自己负责切换到下一个状态。

## C6.16 命令（Command）的概念

**意图**：把请求封装成对象，从而可以用不同的请求对客户进行参数化，对请求排队、记录日志，以及支持撤销。

**类图角色**：抽象命令 Command，具体命令 ConcreteCommand（持有接收者），接收者 Receiver，调用者 Invoker。

**特点与适用**：命令模式属于行为型模式，把请求封装成对象，使请求的发送者和接收者解耦，适用于需要对请求排队、记录日志、支持撤销和重做、实现事务的场合，例如遥控器按钮、编辑器的撤销。支持撤销的做法是命令除了 execute 方法，还提供 undo 方法，由调用者保存已执行的命令历史。缺点是每个具体操作都对应一个命令类，类的数量会增多。宏命令是把多个命令组合在一起，一次执行。

## C6.17 责任链（Chain of Responsibility）的概念

**意图**：使多个对象都有机会处理请求，从而避免请求的发送者和接收者之间的耦合。把这些对象连成一条链，沿着链传递请求，直到有一个对象处理它。

**类图角色**：抽象处理者 Handler（持有后继，声明 handle），具体处理者 ConcreteHandler。

**特点与适用**：责任链模式属于行为型模式，请求沿着处理者组成的链传递，直到有一个处理者处理它，请求的发送者不需要知道谁会处理请求，适用于审批流程、异常处理、过滤器链、日志级别处理。它降低了发送者与接收者的耦合，也可以动态地调整链中的处理者；缺点是请求不保证一定被处理，链太长会影响性能。Java Web 中的过滤器链（Filter）就是责任链模式的应用。

## C6.18 迭代器（Iterator）的概念

**意图**：提供一种方法顺序访问聚合对象中的各个元素，而又不暴露该对象的内部表示。

**类图角色**：抽象聚合 Aggregate（声明 createIterator），具体聚合，抽象迭代器 Iterator（hasNext、next），具体迭代器。

**特点与适用**：迭代器模式属于行为型模式，提供一种顺序访问聚合对象中各个元素、又不暴露其内部表示的方法。它把遍历的职责从聚合对象中分离出来，使聚合对象可以支持多种遍历方式，并且可以同时有多个遍历在进行，因为每个迭代器各自保存自己的游标。Java 集合框架中的 Iterator 接口就是迭代器模式的应用，它的核心方法是 hasNext 和 next。

## C6.19 访问者（Visitor）的概念

**意图**：表示一个作用于某对象结构中的各元素的操作。可以在不改变各元素的类的前提下定义作用于这些元素的新操作。

**类图角色**：抽象访问者 Visitor（对每种元素声明一个 visit 方法），具体访问者，抽象元素 Element（声明 accept），具体元素。

**特点与适用**：访问者模式属于行为型模式，适用于对象结构稳定、但需要经常增加新操作的场合：增加新的访问者（新操作）很容易，不用修改元素类；但增加新的元素类型很困难，要修改抽象访问者和所有具体访问者。访问者模式通过 accept 和 visit 两次方法调用实现双分派，使操作同时取决于访问者的类型和元素的类型。

## C6.20 备忘录（Memento）的概念

**意图**：在不破坏封装性的前提下，捕获一个对象的内部状态，并在该对象之外保存这个状态，以后可以把对象恢复到原先保存的状态。

**类图角色**：发起人 Originator（创建和恢复备忘录），备忘录 Memento（保存状态），管理者 Caretaker（保管备忘录）。

**特点与适用**：备忘录模式属于行为型模式，适用于需要保存和恢复对象状态的场合，例如编辑器的撤销、游戏的存档、事务回滚。它在不破坏封装的前提下保存状态：只有发起人能读取备忘录里的状态，管理者只保管备忘录。缺点是如果状态数据很大或保存很频繁，会占用较多内存。

## C6.21 中介者（Mediator）的概念

**意图**：用一个中介对象封装一系列对象的交互，使各对象不需要显式地互相引用，从而降低耦合，并可以独立地改变它们之间的交互。

**类图角色**：抽象中介者 Mediator，具体中介者 ConcreteMediator（持有所有同事），同事类 Colleague（持有中介者）。

**特点与适用**：中介者模式属于行为型模式，用一个中介对象封装一组对象之间的交互，把同事对象之间复杂的网状多对多关系变成以中介者为中心的星形一对多关系，降低耦合，例如聊天室、飞机场的塔台调度、MVC 中的控制器。缺点是中介者本身可能变得非常复杂，成为难以维护的「上帝对象」。中介者模式与观察者模式的区别：中介者集中控制同事之间的交互，观察者则是主题单向广播通知。

## C6.22 设计模式的分类与设计原则

下午题六考查的设计模式都出自 GoF 的 23 种设计模式，按目的分为创建型、结构型、行为型三类。
创建型模式（5 种）：单例、工厂方法、抽象工厂、建造者、原型，关注对象的创建。
结构型模式（7 种）：适配器、桥接、组合、装饰器、外观、享元、代理，关注类和对象的组合。
行为型模式（11 种）：责任链、命令、解释器、迭代器、中介者、备忘录、观察者、状态、策略、模板方法、访问者，关注对象之间的职责分配和交互。

**设计原则**：开闭原则要求软件实体对扩展开放、对修改关闭，工厂方法、策略、装饰器、观察者等模式都体现了这一原则。
依赖倒置原则要求面向接口编程，依赖抽象而不是依赖具体类，代码填空题里变量和参数的类型写成抽象类型就是这个原因。
合成复用原则要求优先使用组合而不是继承，桥接、装饰器、策略、状态都用组合。

**模式识别**：要让接口不兼容的类一起工作，用适配器；要给复杂的子系统一个简单入口，用外观；要保证全局只有一个实例，用单例。
