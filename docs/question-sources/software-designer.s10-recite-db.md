# 软件设计师（中级）基础知识速记（数据库技术基础）

## 10.1 数据库基本概念与分布式数据库

**一、DBS 组成**：数据库（DB）+ 硬件 + 软件 + 人员（DBA）。

**二、三级模式 + 两映像**

| 模式 | 别名 | 对应 |
|---|---|---|
| 外模式 | 用户模式 / 子模式 | **视图** |
| 概念模式（模式） | 逻辑模式 | **基本表** |
| 内模式 | 存储模式 | **存储文件** |

**两级映像**

- **外模式 / 模式映像**：**逻辑独立性**（改模式时改这个映像，应用程序不变）。
- **模式 / 内模式映像**：**物理独立性**（改存储方式时改这个映像，逻辑结构不变）。

> ⚠ 创建聚簇索引改的是**内模式**。视图 = 外模式；基本表 = 模式；存储文件 = 内模式。

**三、分布式数据库**

- **水平分片**：按行（元组）切分。
- **垂直分片**：按列（属性）切分，**必须保留主码**。

**分布透明性 4 级**

| 透明性 | 含义 |
|---|---|
| 分片透明（最高级） | 用户不知如何分片 |
| 位置透明 | 用户不知分片在哪台机器 |
| 逻辑透明（局部映像） | 用户不知局部 DBMS 用什么数据模型 |
| 复制透明 | 用户不知数据在网络上如何复制 |

**四、大数据 4V**：Volume（大量）、Variety（多样）、Value（价值密度低）、Velocity（快速）。

## 10.2 E-R 模型

**一、E-R 图符号**

| 图形 | 表示 |
|---|---|
| 矩形 | 实体 |
| 椭圆 | 属性 |
| 菱形 | 联系 |
| 直线 | 连接 |

**二、三种联系**：1:1（一对一）、1:n（一对多）、m:n（多对多）。

**三、E-R 转关系模式（必背）**

| 联系类型 | 转换规则 |
|---|---|
| 1:1 | 联系可并入任意一端实体，或单独成模式 |
| 1:n | 联系可并入 n 端（加入一端主码） |
| m:n | **必须单独成一个关系模式**，主码 = 两端主码联合 |

> ⚠ m:n 联系的关系模式关键字 = **两端实体的主码组合**。

## 10.3 关系代数

**一、基本名词**

- **元组**：行（记录）。
- **属性**：列（字段）。
- **域**：属性取值范围。
- **候选码**：能唯一标识元组的属性组。
- **主码**：选中的候选码。
- **主属性**：包含在任一候选码中的属性。
- **外码**：本关系不是码，但引用其他关系的码。

**二、5 种基本运算**

| 运算 | 符号 | 说明 |
|---|---|---|
| 并 | R ∪ S | 两个结构相同的关系合并 |
| 差 | R - S | 在 R 中但不在 S 中 |
| 广义笛卡儿积 | R × S | 列相加、行相乘 |
| 选择 | σ<条件>(R) | 选行（水平方向） |
| 投影 | π<列>(R) | 选列（垂直方向） |

**三、扩展运算**

| 运算 | 说明 |
|---|---|
| 交 | R ∩ S = R - (R - S)（可由基本运算导出） |
| 连接 | 按条件拼接 |
| **自然连接** ★ | 同名属性等值连接 + 去掉重复列 |
| 除 | R ÷ S：找 X 上分量，其象集包含 S 的投影 |
| 外连接 | 左 / 右 / 全外连接，保留不匹配的元组 |

## 10.4 SQL 语言

**一、SELECT 基本结构**

```sql
SELECT [DISTINCT] <列>
FROM <表>
WHERE <条件>
GROUP BY <列> HAVING <组条件>
ORDER BY <列> [ASC | DESC]
```

子句对应关系：

| SQL | 关系代数 |
|---|---|
| SELECT | 投影 π |
| FROM | 笛卡儿积 × |
| WHERE | 选择 σ |

**二、授权语句**

- 授权：`GRANT 权限 ON 表 TO 用户 [WITH GRANT OPTION];`
- 收权：`REVOKE 权限 ON 表 FROM 用户;`

> ⚠ WITH GRANT OPTION = 允许把权限再转授给别人。

## 10.5 关系规范化（重点）

**一、函数依赖**

- **完全函数依赖**：X → Y，且去掉 X 任一属性就不成立。
- **部分函数依赖**：X → Y，但 X 的真子集也能决定 Y。
- **传递函数依赖**：X → Y，Y → Z，且 Y 不 → X。

**二、Armstrong 公理**

| 规则 | 内容 |
|---|---|
| 自反律 | 若 Y ⊆ X，则 X → Y |
| 增广律 | 若 X → Y，则 XZ → YZ |
| 传递律 | 若 X → Y，Y → Z，则 X → Z |
| 合并律 | X → Y，X → Z ⇒ X → YZ |
| 伪传递律 | X → Y，WY → Z ⇒ XW → Z |
| 分解律 | X → YZ ⇒ X → Y，X → Z |

**三、三大范式**

| 范式 | 条件 | 消除什么 |
|---|---|---|
| 1NF | 每个属性不可再分 | —— |
| 2NF | 在 1NF 基础上，消除非主属性对码的**部分依赖** | 部分函数依赖 |
| 3NF | 在 2NF 基础上，消除非主属性对码的**传递依赖** | 传递函数依赖 |

## 10.6 数据库控制：事务、故障、并发与封锁

**一、事务 ACID**

| 特性 | 含义 |
|---|---|
| 原子性 Atomicity | 要么都做，要么都不做 |
| 一致性 Consistency | 从一个一致状态到另一个一致状态 |
| 隔离性 Isolation | 并发事务间互不干扰 |
| 持久性 Durability | 提交后永久有效，即使系统故障 |

> ⚠ 提交后更新即使未写盘也不丢失 → **持久性**。

**二、4 类故障**

| 故障 | 说明 |
|---|---|
| 事务内部故障 | 如除数为 0、事务回滚 |
| 系统故障（软故障） | CPU 故障、OS 故障、停电 |
| 介质故障（硬故障） | 磁盘损坏，**破坏性最大** |
| 计算机病毒 | 人为破坏 |

**三、恢复原理**

- 建立冗余：**数据转储 + 日志文件**。
- 日志用于：事务故障恢复 + 系统故障恢复 + 协助介质故障恢复。

**四、并发问题（3 类）**：丢失更新、不可重复读、读脏数据。

**五、封锁协议**

| 协议 | 加锁规则 | 解决问题 |
|---|---|---|
| 一级 | 改 R 前加 X 锁，事务结束释放 | 丢失更新 |
| 二级 | 一级 + 读 R 前加 S 锁，读完即释放 | + 读脏数据 |
| 三级 | 一级 + 读 R 前加 S 锁，**事务结束释放** | + 不可重复读 |

**两种锁**

- **X 锁（排他锁 / 写锁）**：其他事务不能再加任何锁。
- **S 锁（共享锁 / 读锁）**：其他事务可加 S 锁，但不能加 X 锁。
