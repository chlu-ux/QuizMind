# 软件设计师下午题六：设计模式代码填空题库（设计文档）

> 本文是「软件设计师（中级）下午题 · 试题六（设计模式，Java / C++ 代码填空）」专项题库的设计说明（题库按语言拆成 Java、C++ 两个独立题库，讲义是 `software-designer.t6-pattern-java.md` / `-cpp.md`，下文的小节编号是拆分前的合并编号：Java 语法 T6.1、C++ 语法 T6.2、模式 T6.3～T6.23，拆分后两份讲义里都是 T6.1 语法、T6.2～T6.22 为模式）：考什么、题目怎么出、怎么导入。讲义与题目文件的格式、导入流程与其他批次完全一致，见 [README](README.md)。

## 1. 考试里的这一题

| 项 | 内容 |
|---|---|
| 位置 | 下午卷（应用技术，150 分钟）共 6 题，做 5 题：试题一至四必做（数据流图、数据库 E-R 设计、UML、算法），**试题五、试题六二选一** |
| 试题五 / 试题六 | 同一类题的两个语言版本：通常试题五用 C++、试题六用 Java，**考同一个设计模式场景**，二选一作答，各 15 分。本题库把两种语言都覆盖 |
| 题型 | 设计模式代码填空。先给一段需求说明和类图（UML），再给对应的代码框架，留出 **5 个左右的空**，每空约 3 分 |
| 题目特点 | 代码框架有模式的**固定骨架**：抽象产品 / 具体产品、抽象工厂 / 具体工厂、Subject / Observer 等。读懂类图就能确定大部分空 |
| 难点 | 不是模式本身难，而是**语法细节**：`extends` 还是 `implements`，C++ 要不要 `virtual`、`= 0`、`public`，指针用 `->` 还是 `.`，`static` 成员怎么初始化 |

### 1.1 填空类型

| 类型 | 举例 | 题库里的标签 |
|---|---|---|
| 类名 / 接口名 | `Factory`、`Product`、`Component`、`Implementor` | `填空·类名` |
| 继承 / 实现关键字 | `extends`、`implements`、`: public`、`virtual`、`abstract`、`static` | `填空·关键字` |
| 方法名 / 参数 | `createProduct()`、`attach(Observer o)`、`accept(Visitor v)` | `填空·方法` |
| 业务逻辑（少量） | `return new ConcreteProductA();`、`observers.add(o);`、`state.handle(this);` | `填空·逻辑` |

### 1.2 高频模式

按考试出现的频率和代码骨架的清晰程度，把模式分成三档（频率是经验判断，不是统计）：

| 档次 | 模式 |
|---|---|
| 高频 | 工厂方法、抽象工厂、单例、策略、观察者、模板方法、装饰器、组合、适配器、状态、命令、访问者 |
| 中频 | 建造者、桥接、外观、代理、责任链、备忘录、中介者 |
| 低频 | 原型、迭代器 |

题库对 21 个模式一视同仁地各出一个 Java 案例和一个 C++ 案例；高频模式放在复习的优先位置，做题时可以先按模式（知识点）刷高频的那几个。

## 2. 题库设计

### 2.1 一题一空

真题是「一个案例 5 个空」。为了能在 App 里逐空作答、逐空判分，题库把每个空做成一道**单选题**：

- 题干 = 一句话的场景说明 + **类图（SVG）** + **完整的代码框架**，其他空已经填好，**只留一个空**，用 `______` 表示；
- 4 个选项，都是代码片段（纯文本，不加反引号），干扰项取自真实的易错写法：关键字写错、Java 写法用在 C++ 里、角色类名张冠李戴、少了 `virtual` / `static` 等；
- 解析说明这个空为什么这样填，并指出常见错误；
- 同一个小节里同一种语言的几道题，就是同一个案例的几个空，连着做完就相当于做完了一道真题。

### 2.2 每个模式的组成

每个模式 = 1 个类图 + 1 个 Java 案例 + 1 个 C++ 案例，每个案例 2～4 个空，类型尽量混合，所以每个模式 5～7 题。代码都**真实编译、运行过**（Java 用 `javac`，C++ 用 `clang++ -std=c++17`），保证不是写错的伪代码；每个干扰项也都编译运行过，确认它确实会编译失败或输出不同（只有少数访问修饰符 `public / protected / private` 的区别无法靠输出判断，由解析说明）。

类图由脚本按案例数据画成静态 SVG（带 `interface`、抽象类斜体、继承 / 实现 / 依赖 / 聚合等标准线型）。类图和代码一一对应；原型模式的 Java 与 C++ 写法不同（`Cloneable` 与自定义的 `Prototype`），所以有两张图。

### 2.4 概念题

代码填空之外，每个模式还有 3 道概念题（意图、角色、适用场景、优缺点、易混模式辨析），另有一节「设计模式的分类与设计原则」（创建型 / 结构型 / 行为型的归属、开闭原则、依赖倒置原则、合成复用原则、模式识别）10 题，共 73 题。概念题放在单独的讲义 `software-designer.t6-pattern-concept.md`（22 个小节，编号 C6.1～C6.22）里，和代码填空题导入同一个题库。分成两份文档，是因为改动已导入的讲义会让那些小节的旧题过期。

- 概念小节的正文由脚本拼成：该模式在代码讲义里的「意图」「类图角色」两行 + 「特点与适用」一段（在 `pattern-code/concepts.py` 里），所以这份讲义是生成的，不要手改。
- 标签第三项用 `概念·意图 / 概念·角色 / 概念·场景 / 概念·优缺点 / 概念·辨析`；第二项仍是模式名，所以「按知识点刷题」选某个模式时，代码题和概念题会在一起。
- 干扰项的长度和正确答案相近，避免靠选项长短猜答案。

### 2.5 标签与难度

- `tags` 第一项固定为 `下午题六`，第二项是模式名（语言基础小节用语言名），第三项是填空类型（见 §1.1）或概念类型（见 §2.4）。
- 难度 1～5：1～2 是看类图就能填的角色类名和固定关键字；3 是要懂语法细节（`virtual`、`= 0`、`->`、`static` 初始化）；4～5 是业务逻辑和易混的角色对应关系。

## 3. 解题套路（也是讲义里反复强调的）

1. **先看类图再看代码**：箭头 `△` 空心三角表示继承 / 实现，虚线加三角是实现接口，实线菱形是聚合 / 组合，虚线箭头是依赖。类图上有的类名、方法名，代码里的空基本就是它们。
2. **找骨架**：这个案例属于哪个模式，该模式的角色（Creator / Product、Subject / Observer……）在代码里分别是哪个类。
3. **语言关键字**：
   - Java：类继承类用 `extends`，类实现接口用 `implements`，接口继承接口用 `extends`；抽象方法 `abstract`，没有指针，用对象引用。
   - C++：没有 `interface`，用纯虚函数 `virtual 返回类型 f() = 0;` 的抽象类；继承写 `: public 基类`；多态靠指针或引用，指针调用成员用 `->`；有 `delete` 的基类要有虚析构函数。
4. **返回类型与参数类型要用抽象类型**（接口 / 基类），这是「依赖抽象」的体现：工厂方法返回 `Product` 而不是 `ConcreteProduct`。
5. **对象创建在具体类里**：`new ConcreteProduct()` 只会出现在具体工厂、具体建造者里。

## 5. 导入

建成独立题库「软件设计师·下午题六（设计模式代码填空）」，不并进上午的软件设计师题库：

```bash
cd server
go run ./cmd/devseed -config config.yaml \
  -doc ../docs/question-sources/software-designer.t6-pattern-code.md \
  -questions ../docs/question-sources/software-designer.t6-pattern-code.questions.json \
  -bank "软件设计师·下午题六（设计模式代码填空）" -approve -1
go run ./cmd/devseed -config config.yaml \
  -doc ../docs/question-sources/software-designer.t6-pattern-concept.md \
  -questions ../docs/question-sources/software-designer.t6-pattern-concept.questions.json \
  -bank "软件设计师·下午题六（设计模式代码填空）" -append -approve -1
```

导入要用**新版**服务端代码（`go run` 自动用当前源码），因为这个题库依赖三处校验规则的调整：

| 规则 | 调整 | 原因 |
|---|---|---|
| 题干长度（`validate.go`） | 含 ``` 代码块的题干上限 2000 字，其他题仍是 300 字 | 代码框架一般 600～1500 字 |
| 选项去重（`validate.go`） | 含代码符号（`. -> :: * & ++ ( )` 等）、单个标识符或 `a.b` 的选项按原样（区分大小写和符号）比较 | 原来只比较字母和数字，`a.b` / `a->b` / `a::b` 和 `Logger` / `Logger*` 被当成重复选项 |
| 近似题去重（`dedupe.go`） | 两道题的题干都含代码块时，只做完全重复检查，不再做近似检查 | 同一段代码、不同位置的空，题干几乎一样，会被误判为近似题 |

题干里的类图（`uml/pattern-*.svg`）会被上传并改写成 `media:` 引用。

### 已知不足

- 真题是「一个案例 5 个空」，这里每个案例的每种语言只有 2～4 个空，需要连着做同一模式的 5～7 题才相当于一整道真题。
