# 软件设计师（中级）基础知识速记（软件工程基础知识）

## 6.1 软件生存周期与 CMM

**一、软件生存周期 8 阶段（国标）**

1. 可行性研究与计划
2. 需求分析
3. 总体设计（概要设计）
4. 详细设计
5. 程序实现（编码 + 单元测试）
6. 集成测试
7. 确认测试
8. 使用与维护

**二、CMM 5 级**

| 级别 | 名称 | 特点 |
|---|---|---|
| 1 | **初始级** | 过程混乱，靠个人英雄 |
| 2 | **可重复级** | 建立基本项目管理，能重复以前成功 |
| 3 | **已定义级** | 过程文档化、标准化，组织标准过程 |
| 4 | **已管理级** | 有详细度量标准，过程和质量可定量控制 |
| 5 | **优化级** | 定量反馈，持续过程改进 |

> ⚠ 1 级最低，5 级最高。CMMI 连续式能力等级 CL0 ~ CL5：CL1（已执行）→ CL2（已管理）→ CL3（已定义）→ CL4（定量管理）→ CL5（持续优化）。

## 6.2 软件过程模型与敏捷方法

**软件过程模型**

| 模型 | 特点 | 适用场景 |
|---|---|---|
| **瀑布模型** | 线性顺序，文档驱动，**推迟到后期才能看到软件**；缺乏灵活性 | 需求明确、稳定 |
| **增量模型** | 分批交付可运行版本，第一个增量是核心产品；融合瀑布 + 迭代 | 需求分批、急需核心产品 |
| **原型模型** | 快速构建可运行原型，用户反馈修改；适合**需求不清** | 需求不明确、规模不大 |
| **螺旋模型** | **瀑布 + 演化 + 风险分析**；每周期 4 步：计划、风险分析、工程、用户评估 | **庞大、复杂、高风险**系统 |
| **喷泉模型** | 面向**对象**，迭代无间隙，各阶段无明显界线；支持重用 | 面向对象开发 |
| **统一过程 UP** | 用例和风险驱动、以架构为中心、迭代增量；4 阶段：初始、精化、构建、移交 | 大型 OO 项目 |
| **敏捷方法** | 快速交付、拥抱变化 | 需求变化快 |

**敏捷方法**

- **XP 极限编程**：4 价值观（沟通、简单、反馈、勇气）；实践含**测试先行、结对编程、持续集成、简单设计**。
- **Scrum 并列争球法**：30 天一个“冲刺”，按需求优先级迭代。
- **水晶法**：每个项目需不同策略。
- **AUP**：大型上连续、小型上迭代。

> ⚠ XP 是**先写测试代码再写程序**（不是写完再测）。

## 6.3 需求分析与系统设计

**一、需求的本质**

需求描述系统“做什么（What）”，不是“怎么做（How）”。

- **功能需求**：软件要执行的功能（如“每月发工资”）。
- **非功能需求**：性能、质量约束（如响应时间 ≤ 3 秒、100 用户并发）。

**二、需求工程 6 阶段**

需求获取 → 需求分析与协商 → 系统建模 → 需求规约 → 需求验证 → 需求管理。

**三、结构化分析 SA 模型（3 种图）**

| 模型 | 工具 |
|---|---|
| 数据模型 | **E-R 图（ERD）** |
| 功能模型 | **数据流图（DFD）** |
| 行为模型 | **状态转换图（STD）** |

- 模型核心是**数据字典**。
- 用 DFD 建模时，外部人员（患者、考生）是**外部实体**；用 ERD 建模时是**实体**。

**四、概要设计（总体设计）任务**

- 把系统按功能**划分模块**。
- 确定模块功能、调用关系、接口。
- **数据结构与数据库设计（概念 / 逻辑设计）**。
- 编写概要设计文档。

**五、详细设计任务**

- 每个模块的**详细算法设计**。
- 模块内数据结构设计。
- **数据库物理设计**。
- 输入 / 输出格式、用户界面设计。

## 6.4 系统测试

**一、测试 4 步**：单元测试 → 集成测试 → 确认测试 → 系统测试。

| 测试阶段 | 测试对象 | 主要方法 |
|---|---|---|
| 单元测试（模块） | 单个模块内部逻辑 | **白盒测试**为主 |
| 集成测试 | 模块间接口 | 自顶向下 / 自底向上 / 回归 / 冒烟 |
| 确认测试 | 软件是否满足需求 | **α 测试**（开发者现场）、**β 测试**（用户现场） |
| 系统测试 | 软硬件结合整体 | 与需求对比 |

**二、测试方法**

- **静态测试**：不运行程序，人工审查 / 静态分析。
- **动态测试**：运行程序，分黑盒和白盒。

**三、黑盒测试（功能测试）**

不看内部结构，只测输入输出。常用技术：

1. **等价类划分**（有效 / 无效等价类）。
2. **边界值分析**（取边界及边界外值，如 0 ~ 150 取 0、150、-1、151）。
3. **错误推测法**。
4. **因果图**（→ 判定表）。

**四、白盒测试（结构测试）覆盖强度（由弱到强）**

语句覆盖 < 判定覆盖（分支覆盖）< 条件覆盖 < 判定 / 条件覆盖 < 条件组合覆盖 < 路径覆盖。

> ⚠ 语句覆盖最弱；路径覆盖最强。

**五、McCabe 环路复杂度**

公式：**V(G) = m - n + 2p**。

- m = 边数，n = 结点数，p = 强连通分量数（通常 = 1）。
- 例：n = 6，m = 9，p = 1 → V(G) = 9 - 6 + 2 = **5**。
- 环路复杂度 = **独立路径数** = 至少需要的测试用例数。

**六、调试方法**

| 方法 | 特点 |
|---|---|
| 试探法 | 效率低，适合简单程序 |
| 回溯法 | 从错误点反向追踪，适合小程序 |
| 对分查找法 | 缩小错误范围 |
| **归纳法** | 从错误现象收集数据 → 假设原因 → 验证 |
| **演绎法** | 列出所有可能原因 → 逐一排除 |

> ⚠ 测试发现错误，**调试由开发人员做**。

## 6.5 系统维护

**一、可维护性 3 评价指标**：**可理解性、可测试性、可修改性**（不含一致性）。

**二、软件维护 4 类型**

| 类型 | 目的 | 例子 |
|---|---|---|
| **改正性维护** | 改发现的错误 | 改 bug |
| **适应性维护** | 适应环境变化 | 操作系统升级、数据格式更改 |
| **完善性维护** | 增强功能、改善界面 | 让界面更友好、加新功能 |
| **预防性维护** | 为未来改进 | 提前重构 |

> ⚠ 数据格式变了 → **适应性**；界面更友好 → **完善性**。维护阶段时间比开发更长、工作量更大。

## 6.6 软件项目管理

**一、4P**：人员（Person）、产品（Product）、过程（Procedure）、项目（Project）。

**二、COCOMO II 3 阶段模型**

| 阶段模型 | 规模估算 |
|---|---|
| 应用组装模型 | **对象点** |
| 早期设计阶段模型 | **功能点** |
| 体系结构阶段模型 | **源代码行数（LOC）** |

**三、Gantt 图 vs PERT 图**

| 对比项 | Gantt 甘特图 | PERT 图 |
|---|---|---|
| 形式 | 水平条形图 | 有向图（箭头 = 任务，结点 = 事件） |
| 优点 | 直观，能看清并行任务 | 能展示任务依赖关系 |
| 缺点 | **不能清晰展示依赖关系** | 不如图直观 |
| 关键路径 | 不直接体现 | **关键路径 = 最长路径，决定最短工期** |
| 松弛时间 | —— | 非关键路径任务可延迟时间 |

空任务：**虚线箭头，耗时 0**。

## 6.7 配置管理、风险、软件质量与工具

**一、软件配置管理 SCM**

- 目标：标识变更、控制变更、确保正确实现、报告变更。
- 主要活动：**基线、软件配置项、版本控制、变更控制、配置状态报告**。

> ⚠ **风险管理不属于配置管理。**

**二、风险**

- 两个特性：**不确定性 + 损失**。
- 类型：项目风险（进度、预算、人员）、技术风险、商业风险。

> ⚠ “团队能良好沟通”**不是风险**（是好事）。

**三、软件质量 ISO/IEC 9126：6 大质量特性**

| 特性 | 子特性 |
|---|---|
| 功能性 | 适合性、准确性、互操作性、**安全性**、依从性 |
| 可靠性 | **成熟性、容错性、易恢复性** |
| 易使用性 | **易理解性、易学性、易操作性** |
| 效率 | 时间特性、资源特性 |
| 可维护性 | **易分析性、易改变性、稳定性、易测试性** |
| 可移植性 | 适应性、易安装性、一致性、易替换性 |

**四、软件工具**

- **开发工具**：需求分析、设计、编码排错、测试。
- **维护工具**：版本控制、文档分析、开发信息库、逆向工程、再工程。
- **管理 / 支持工具**：项目管理、**配置管理**、软件评价。

> ⚠ 配置管理工具属于**管理 / 支持工具**，不是维护工具。
