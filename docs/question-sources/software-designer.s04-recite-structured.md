# 软件设计师（中级）基础知识速记（结构化开发方法）

## 4.1 系统设计基本原理、耦合与内聚

**一、四大设计原理**

| 原理 | 一句话含义 |
|---|---|
| 抽象 | 分层次概括问题，最高层概括描述，最低层是源程序代码 |
| 模块化 | 分而治之，把系统分解成可独立开发、测试、组装的模块 |
| 信息隐蔽 | 把可能变化的因素封装在一个模块内部，模块间少暴露内部细节；提高**可修改性、可测试性、可移植性** |
| 模块独立 | 每个模块完成特定子功能，模块间联系简单；用**耦合、内聚**衡量 |

> 🎯 模块独立目标：**高内聚、低耦合**。

**二、耦合**（从低到高，共 7 级）

耦合 = 模块间联系紧密程度。**越低越好。**

| 级别 | 类型 | 特征关键词 |
|---|---|---|
| 1（最低） | **无直接耦合** | 两模块无直接联系 |
| 2 | **数据耦合** | 传递**基本数据类型**值 |
| 3 | **标记耦合** | 传递**数据结构 / 记录**（如结构体、对象） |
| 4 | **控制耦合** | 传递**控制信息**（开关、标志位），决定执行哪部分 |
| 5 | **外部耦合** | 共享**简单变量**、通信格式、外部设备 |
| 6 | **公共耦合** | 共享**公共数据环境**（全局数据结构、共享通信区、公共内存） |
| 7（最高 / 最差） | **内容耦合** | 一个模块**直接访问**另一模块内部数据 / 代码；**非正常入口转入** |

**三、内聚**（从低到高，共 7 级）

内聚 = 模块内部各元素联系紧密程度。**越高越好。**

| 级别 | 类型 | 特征关键词 |
|---|---|---|
| 1（最低 / 最差） | **偶然（巧合）内聚** | 各成分无任何联系，偶然凑在一起 |
| 2 | **逻辑内聚** | 完成**逻辑上相似**的一组功能（如“所有输入 / 输出”） |
| 3 | **时间内聚（瞬时）** | 同一时间段执行（如初始化、退出） |
| 4 | **过程内聚** | 按**特定次序**执行（如先 A 再 B 再 C） |
| 5 | **通信内聚** | 都在**同一数据结构**上操作 / 同一输入输出 |
| 6 | **顺序内聚** | 前一成分**输出**是后一成分**输入**，顺序衔接 |
| 7（最高 / 最好） | **功能内聚** | 所有元素共同完成**一个功能**，缺一不可 |

## 4.2 结构化分析与数据流图

**一、总体认识**

- 面向**数据流**，自顶向下逐层分解。
- 分析结果 = **4 件套**：① 一套分层**数据流图（DFD）**；② 一本**数据字典（DD）**；③ 一组**小说明**（加工逻辑说明）；④ 补充材料。

> ⚠ **结构图（SC）是设计阶段的**，不属于分析输出。

**二、数据流图（DFD）**

| 元素 | 说明 | 注意 |
|---|---|---|
| 外部实体 | 系统外的人 / 组织，数据的源点 / 终点 | 如考生、考试中心、阅卷老师 |
| 加工 | 数据变换 | **至少 1 入 1 出** |
| 数据存储 | 保存数据（文件 / 数据库） | 可读写 |
| 数据流 | 数据的流向 | **必须经过加工** |

> ⚠ DFD 画的是**数据流**，不是控制流！

**三、加工的 3 种错误**

| 错误名 | 含义 |
|---|---|
| 黑洞 | 有输入无输出 |
| 奇迹 | 有输出无输入 |
| 灰洞 | 输入不足以产生输出 |

**四、DFD 分层**

- **顶层图**：只有 **1 个加工**（代表整个系统），描述系统与外界的数据往来。
- **0 层图**：顶层加工分解后得到，也只有一张。
- **底层图**：最底层，所有加工不再分解，叫**基本加工**。
- 原则：**自顶向下**逐层分解，分解均匀、每个加工数据流不宜过多、**不画控制流**。

## 4.3 数据字典、加工逻辑与用户界面

**一、数据字典（DD）**

- 作用：为 DFD 中每个成分做说明（DFD 只画图不解释）。
- 4 类条目：**数据流、数据项（最小元素）、数据存储、基本加工**。

> ⚠ **不包括外部实体！**

**二、加工逻辑（小说明）3 种描述方法**

| 方法 | 适用场景 |
|---|---|
| 结构化语言 | 介于自然语言和形式语言之间的半形式化语言；外层用顺序 / 选择 / 重复控制结构 |
| 判定表 | 多个**条件组合**与动作对应关系复杂时（清晰表达条件 → 动作） |
| 判定树 | 判定表的变形，**更直观、易理解** |

**三、用户界面设计：Theo Mandel 三大“黄金原则”**

- 用户**操纵控制**。
- **减少**用户的**记忆负担**。
- 保持界面**一致**。

> ⚠ 不包括“界面美观整洁”（那是主观感觉，不是黄金准则）。
