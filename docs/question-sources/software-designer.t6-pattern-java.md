# 软件设计师（中级）下午题六（设计模式代码填空·Java）

## T6.1 Java 的类、接口、继承与多态写法

下午题的设计模式题是填空题，类图和模式的结构都给出了，真正丢分的往往是 Java 与 C++ 的语法细节。这一节先过 Java 的语法点。

Java 中类实现接口用 implements，类继承类用 extends，接口继承接口也用 extends。一个类只能继承一个类，但可以实现多个接口。
Java 中用 abstract 声明抽象类和抽象方法，抽象方法没有方法体，包含抽象方法的类必须声明为抽象类，抽象类不能用 new 创建对象。
Java 中用 final 修饰的方法不能被子类重写，final 修饰的类不能被继承。
Java 中用 super 调用父类的构造函数和被重写的方法，子类构造函数里 super(参数) 必须写在第一行。
Java 接口中声明的方法默认是 public abstract 的。
Java 中用 @Override 注解标注一个方法重写了父类的方法，编译器会检查是否真的重写。
Java 没有指针，对象用引用访问，用点号 . 调用成员，用 new 创建对象，不需要手工释放。

## T6.2 单例（Singleton）

**意图**：保证一个类只有一个实例，并提供一个全局访问点。常用于配置管理器、线程池、日志对象。

**类图角色**：只有一个类，它有一个私有的静态属性 instance、一个私有的构造函数和一个公有的静态方法 getInstance()。

**Java 写法**：构造函数必须是私有的，外部不能用 new 创建对象。获取实例的方法必须是静态方法，因为调用它时还没有对象。静态属性保存唯一的实例。
懒汉式：第一次调用时才用 new 创建唯一的实例，之后直接返回已有的实例。多线程下要给 getInstance 加 synchronized，或者改用饿汉式（类加载时就创建）。

**常见填空**：private / static 关键字；new Config()。

## T6.3 工厂方法（Factory Method）

**意图**：定义一个创建对象的接口，让子类决定实例化哪个类，把对象的创建延迟到子类。

**类图角色**：抽象产品 Product，具体产品 ConcreteProduct，抽象工厂（创建者）Creator，具体工厂 ConcreteCreator。抽象工厂里声明工厂方法，具体工厂重写它。

**Java 写法**：Java 中类实现接口用 implements，类继承类用 extends。
工厂方法的返回类型是抽象产品，子类重写它并返回具体产品。
抽象工厂里的普通方法调用工厂方法获得产品，不关心具体产品是什么。这个普通方法就是父类里固定下来的流程，创建哪个对象由子类决定。

**常见填空**：implements / extends；工厂方法的返回类型（抽象产品）；createProduct() 的调用；new ConcreteProduct()。

## T6.4 抽象工厂（Abstract Factory）

**意图**：提供一个创建一系列相关或相互依赖对象的接口，而无需指定它们的具体类。适用于产品族，例如 Windows 风格和 Mac 风格的界面组件。

**类图角色**：抽象工厂 AbstractFactory，具体工厂 ConcreteFactory；每种产品有一个抽象产品（AbstractProductA、AbstractProductB），以及各系列的具体产品。

**Java 写法**：抽象工厂为每一种抽象产品声明一个创建方法，返回类型是抽象产品。Java 中类实现接口用 implements，类继承类用 extends。
一个具体工厂创建同一个产品族的全部产品，保证风格一致。客户端只依赖抽象工厂和抽象产品，不依赖具体类，更换产品族只需要换一个具体工厂。

**常见填空**：创建方法的返回类型；implements；new 具体产品；客户端的构造函数参数类型（抽象工厂）。
**和工厂方法的区别**：工厂方法只有一个产品等级结构，抽象工厂有多个产品等级结构，一个具体工厂负责创建整个产品族。

## T6.5 建造者（Builder）

**意图**：将一个复杂对象的构建与它的表示分离，使同样的构建过程可以创建不同的表示。

**类图角色**：产品 Product，抽象建造者 Builder（声明各个构建步骤和 getResult），具体建造者 ConcreteBuilder，指挥者 Director（控制构建顺序）。

**Java 写法**：Java 中类实现接口用 implements，类继承类用 extends；抽象建造者通常是抽象类，具体建造者用 extends 继承它。
指挥者只依赖抽象建造者，构建的顺序由指挥者控制。
指挥者按固定的顺序调用建造者的各个步骤，最后取得产品。

**常见填空**：extends；指挥者构造函数的参数类型（抽象建造者）；步骤方法名；getResult()。

## T6.6 原型（Prototype）

**意图**：用原型实例指定要创建对象的种类，并通过复制这个原型来创建新的对象。适用于创建对象成本较高，或需要保存对象状态副本的场合。

**类图角色**：抽象原型 Prototype（声明 clone 方法），具体原型 ConcretePrototype（实现 clone）。

**Java 写法**：Java 的原型模式要实现 Cloneable 接口，并调用 Object 的 clone 方法完成复制，写成 super.clone()。Cloneable 是标记接口，没有方法。
原型的克隆方法返回的是原对象的副本。重写 clone 时可以把返回类型改成本类，调用者不用强制转换。
Object 的 clone 是浅拷贝：引用类型的成员仍然共享同一个对象。

**常见填空**：implements Cloneable；super.clone()；clone 的返回类型。

## T6.7 适配器（Adapter）

**意图**：把一个类的接口转换成客户端期望的另一种接口，使原本由于接口不兼容而不能一起工作的类可以一起工作。

**类图角色**：目标接口 Target，被适配者 Adaptee（已有的类，接口不符合要求），适配器 Adapter，客户端 Client。对象适配器通过组合持有被适配者；类适配器通过继承被适配者实现。

**Java 写法**：适配器实现客户端期望的目标接口，并持有被适配的对象，用 implements 实现目标接口，字段的类型是被适配者的类。
适配器在目标接口的方法里，把调用转发给被适配者已有的方法。

**常见填空**：implements；被适配者的类名；转发调用的方法名；客户端参数类型。

## T6.8 桥接（Bridge）

**意图**：把抽象部分与实现部分分离，使它们可以独立变化。用组合代替继承，避免形状×颜色这样的多维度导致子类爆炸。

**类图角色**：抽象部分 Abstraction（持有实现部分的引用），扩展抽象部分 RefinedAbstraction，实现部分接口 Implementor，具体实现部分 ConcreteImplementor。

**Java 写法**：桥接模式中抽象部分持有实现部分的抽象接口，两者通过组合连接。这个持有的引用就是「桥」。
Java 中类实现接口用 implements，类继承类用 extends。Java 的子类构造函数用 super(参数) 调用父类的构造函数。
抽象部分的成员是实现部分接口的指针，同样是桥接模式中抽象部分持有实现部分的抽象接口，两者通过组合连接。

**常见填空**：抽象部分里实现部分的类型；extends；super(...)；通过引用调用实现部分的方法。

## T6.9 组合（Composite）

**意图**：将对象组合成树形结构以表示「部分—整体」的层次，使客户端对单个对象和组合对象的使用具有一致性。

**类图角色**：抽象构件 Component，叶子 Leaf，组合节点 Composite（持有子构件列表，提供 add、remove）。

**Java 写法**：组合模式中叶子节点和组合节点都继承同一个抽象构件。
组合节点保存的子节点是抽象构件类型，既可以是叶子也可以是组合节点，例如 List<Component>。
组合节点通过遍历子节点并调用它们的同名方法实现递归。

**常见填空**：extends；列表的元素类型；add；递归调用的方法名。

## T6.10 装饰器（Decorator）

**意图**：动态地给对象添加额外的职责。比继承更灵活：不同的装饰器可以任意组合、层层嵌套，而不用为每种组合写一个子类。

**类图角色**：抽象构件 Component，具体构件 ConcreteComponent，抽象装饰器 Decorator（实现 Component 并持有一个 Component），具体装饰器 ConcreteDecorator。

**Java 写法**：装饰器和被装饰对象实现同一个抽象构件接口，并且持有一个抽象构件的引用。
装饰器在自己的方法里先调用被装饰对象的方法，再附加自己的功能，例如 beverage.cost() + 5。

**常见填空**：implements；装饰器持有的类型；抽象装饰器的构造函数调用；对被装饰对象的方法调用。

## T6.11 外观（Facade）

**意图**：为子系统中的一组接口提供一个一致的高层接口，使子系统更容易使用，减少客户端与子系统的耦合。

**类图角色**：外观 Facade，各个子系统类 SubsystemA、SubsystemB 等。客户端只和外观打交道。

**Java 写法**：外观模式为一组子系统提供统一的高层接口，外观类持有各个子系统对象。
外观类的方法按固定顺序调用各个子系统的方法，客户端不需要知道细节。

**常见填空**：子系统的类名；子系统的方法名；new 子系统。

## T6.12 代理（Proxy）

**意图**：为其他对象提供一种代理，以控制对这个对象的访问。常见的有虚拟代理（延迟加载）、保护代理（权限检查）、远程代理。

**类图角色**：抽象主题 Subject，真实主题 RealSubject，代理 Proxy。

**Java 写法**：代理类和真实主题实现同一个抽象主题接口，代理持有真实主题的引用。
虚拟代理在第一次使用时才创建真实对象，之后复用同一个对象，写成 if (real == null) { real = new RealImage(file); }。
代理类把客户端的请求转发给真实主题，并在转发前后做控制。

**常见填空**：implements；真实主题的类型；new RealImage(file)；转发调用的方法名。

## T6.13 策略（Strategy）

**意图**：定义一系列算法，把每个算法封装起来，并使它们可以相互替换。让算法的变化独立于使用算法的客户。

**类图角色**：上下文 Context，抽象策略 Strategy，具体策略 ConcreteStrategy。

**Java 写法**：策略模式中每个具体策略都实现同一个抽象策略接口，上下文持有抽象策略的引用。
上下文把算法的执行委托给当前持有的策略对象，运行时可以更换策略，通过 setStrategy 设置。

**常见填空**：implements；上下文里策略的类型（抽象策略）；委托调用的方法名。
**和状态模式的区别**：策略由客户端选择并设置，策略之间互不知晓；状态由状态对象自己负责切换到下一个状态。

## T6.14 观察者（Observer）

**意图**：定义对象间的一对多依赖，当一个对象的状态改变时，所有依赖它的对象都得到通知并自动更新。

**类图角色**：主题 Subject（维护观察者列表，提供 attach、detach、notify），抽象观察者 Observer（声明 update），具体观察者 ConcreteObserver。

**Java 写法**：主题（Subject）维护一个抽象观察者的列表，状态改变时遍历列表逐个通知。
主题的 attach 方法把观察者加入列表，detach 方法把观察者从列表移除，列表的添加方法是 add。
状态改变时，主题遍历观察者列表，调用每个观察者的 update 方法。

**常见填空**：列表的元素类型（抽象观察者）；add；update。

## T6.15 模板方法（Template Method）

**意图**：在父类中定义算法的骨架，把某些步骤延迟到子类实现，使子类可以不改变算法结构而重定义某些步骤。

**类图角色**：抽象类 AbstractClass（模板方法 + 抽象步骤 + 具体步骤），具体类 ConcreteClass（实现抽象步骤）。

**Java 写法**：模板方法是父类中定义算法骨架的普通方法，通常声明为 final，不允许子类重写。
父类中把需要子类实现的步骤声明为抽象方法，Java 用 abstract，C++ 用纯虚函数。
Java 中类实现接口用 implements，类继承类用 extends，具体类用 extends 继承抽象类。

**常见填空**：final；abstract；extends；步骤调用。

## T6.16 状态（State）

**意图**：允许一个对象在其内部状态改变时改变它的行为，对象看起来好像修改了它的类。

**类图角色**：上下文 Context（持有当前状态），抽象状态 State，具体状态 ConcreteState。

**Java 写法**：状态模式的上下文持有抽象状态的引用，把行为委托给当前状态对象，调用 state.handle(this)。
状态模式中状态转换由具体状态类完成：处理完后调用上下文的 setState 切换到下一个状态。

**常见填空**：上下文里状态的类型；handle；new 下一个状态；this。

## T6.17 命令（Command）

**意图**：把请求封装成对象，从而可以用不同的请求对客户进行参数化，对请求排队、记录日志，以及支持撤销。

**类图角色**：抽象命令 Command，具体命令 ConcreteCommand（持有接收者），接收者 Receiver，调用者 Invoker。

**Java 写法**：命令模式把请求封装成对象：抽象命令声明 execute 方法，具体命令持有接收者并在 execute 中调用它的方法。
命令模式的调用者只持有抽象命令，通过 execute 触发请求，不依赖具体接收者。具体命令用 implements 实现抽象命令接口。

**常见填空**：implements；接收者的方法名；调用者持有的类型（抽象命令）；execute。

## T6.18 责任链（Chain of Responsibility）

**意图**：使多个对象都有机会处理请求，从而避免请求的发送者和接收者之间的耦合。把这些对象连成一条链，沿着链传递请求，直到有一个对象处理它。

**类图角色**：抽象处理者 Handler（持有后继，声明 handle），具体处理者 ConcreteHandler。

**Java 写法**：责任链中每个处理者持有指向下一个抽象处理者的引用，处理不了的请求转发给后继，写成 next.handle(days)。
责任链中每个处理者只处理自己权限范围内的请求，超出范围就交给后继。转发前要判断后继不为空。

**常见填空**：后继的类型（抽象处理者）；转发调用 next.handle(...)；权限判断的条件。

## T6.19 迭代器（Iterator）

**意图**：提供一种方法顺序访问聚合对象中的各个元素，而又不暴露该对象的内部表示。

**类图角色**：抽象聚合 Aggregate（声明 createIterator），具体聚合，抽象迭代器 Iterator（hasNext、next），具体迭代器。

**Java 写法**：迭代器模式把遍历的职责从聚合对象中分离出来，聚合对象的 getIterator 方法返回一个迭代器对象。
Java 数组的长度用属性 length 表示，不带括号；String 的长度才是 length()，集合的元素个数是 size()。
迭代器的 next 方法返回当前元素，并把游标移到下一个元素，所以用 index++。

**常见填空**：implements；数组的 length；index++；new NameIterator(this)。

## T6.20 访问者（Visitor）

**意图**：表示一个作用于某对象结构中的各元素的操作。可以在不改变各元素的类的前提下定义作用于这些元素的新操作。

**类图角色**：抽象访问者 Visitor（对每种元素声明一个 visit 方法），具体访问者，抽象元素 Element（声明 accept），具体元素。

**Java 写法**：访问者模式的 accept 方法调用访问者的 visit 方法，并把元素自己（this）作为参数传入，称为双分派。
访问者通过 visit 方法的参数访问元素的数据，对不同类型的元素做不同的处理。Java 中类实现接口用 implements，类继承类用 extends。

**常见填空**：visit(this) 里的 this；accept 的参数类型；implements；visit 方法里访问元素的数据。

## T6.21 备忘录（Memento）

**意图**：在不破坏封装性的前提下，捕获一个对象的内部状态，并在该对象之外保存这个状态，以后可以把对象恢复到原先保存的状态。

**类图角色**：发起人 Originator（创建和恢复备忘录），备忘录 Memento（保存状态），管理者 Caretaker（保管备忘录）。

**Java 写法**：备忘录模式中发起人创建备忘录保存自己的内部状态，需要时用备忘录恢复。发起人的 save 方法返回 new Memento(text)，restore 方法的参数是 Memento。
备忘录模式的管理者只负责保存和提供备忘录，不检查也不修改备忘录的内容。管理者的 push 存入，pop 取出。

**常见填空**：new Memento(text)；restore 的参数类型；管理者的取出方法 pop。

## T6.22 中介者（Mediator）

**意图**：用一个中介对象封装一系列对象的交互，使各对象不需要显式地互相引用，从而降低耦合，并可以独立地改变它们之间的交互。

**类图角色**：抽象中介者 Mediator，具体中介者 ConcreteMediator（持有所有同事），同事类 Colleague（持有中介者）。

**Java 写法**：同事对象只持有中介者的引用，通过中介者与其他同事通信，彼此互不引用。
中介者把同事发来的消息转发给除发送者以外的其他同事，所以转发时要判断 u != from。同事发送消息写成 mediator.send(msg, this)。

**常见填空**：同事持有的类型（抽象中介者）；send / receive 的区分；排除发送者。
